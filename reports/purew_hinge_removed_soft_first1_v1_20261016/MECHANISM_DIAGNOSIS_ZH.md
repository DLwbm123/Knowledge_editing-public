# HM HU 证据间隔与外部保护失败诊断

2026-10-16，仅分析已有代码、40个槽日志与已交付评分。结论是：答案目标与证据门不等价；当前保护项的输入范围与外部保护面板不同；四行 removed Fisher 的数值上界不是实际 KL 上界。已确认这些机制缺口，但不能从已有日志唯一识别三道外部错误的具体因果，也不能证明加入某一损失一定修复它们。

## 答案拟合不等于证据依赖

当前答案目标 H 是答案 token 的平均 `ReLU(logit(a*)−logit(a_full))`。证据门则对五视图、两个源答案概念分别计算：

`m(v,c) = mean_concept_tokens[log p(y|x_full,y_<t) − log p(y|x_removed,y_<t)]`。

H 只看 full 输入；HM 的 `loss` 虽接收 removed/anchors 参数，却不使用它们。HU 新增的条件 KL 和 prefix KL 也只作用于 full 输入。它们没有直接要求 full 的答案概率超过 removed。

|终点|HM|HU|
|---|---:|---:|
|完整 CE|0.007141|0.014671|
|hinge|0|0.038995|
|达到实际 a* 的加权 token 比例|100%|91.67%|
|全局最小 a−a*|0.009908|−0.067059|
|hinge 参数梯度范数|0|3.820354|
|正证据间隔|5/10|5/10|
|最小证据间隔|−0.0000584262|−0.0002896870|

HM 是最直接的反例：所有目标位置都达到 a*，完整 hinge 及其梯度为零，仍有五个负间隔。因此不能把本次证据门失败统一解释为“答案尚未学会”或“再多几步就好”。HU 尚有少数 token 未达 a*，但这一点不足以解释 HM 的失败。

数学上，若 full 的目标概率为0.99，removed为0.995，a*=0.95，则 hinge=0、CE约0.01005，而 log(0.99/0.995)<0。两种输入同时高置信预测目标即可出现该情况。实际日志支持这一现象的终态符号，但没有逐概念的初始/终点 full 与 removed logp 分解，无法复原各概念何时改变、由哪侧变化主导。五个负数也不能据此指认属于同一概念。

源末 `validate_margins` 只是准入门。答案/evidence 探针和10行 margin 统计的出生发生在该门之后；两臂提前以 `EVIDENCE_MARGIN_NOT_ADMITTED` 返回，未建立这些统计。不能说“margin 保护机制已生效但失败”；它没有参与这次首源学习。

## 四行 Fisher 与实际 KL 已明确脱节

`worker.probes` 在首次写入前，对当前源五个 removed 视图的答案位置构造四个随机 Fisher 探针。`Block.inspect` 的上界覆盖这个有限二次型及其算术误差，不覆盖未采样方向、模型非线性余项或外部病例分布。

|量|HM|HU|
|---|---:|---:|
|第1槽实际 removed KL 加权均值|0.041226|0.041226|
|第1槽 removed 代理风险上界|0.00998924|0.00998924|
|终点实际 removed KL 加权均值|3.617273|2.339240|
|终点 removed 代理风险上界|0.00999980|0.00994636|
|终点 Base 代理风险上界|0.00151214|0.00148502|
|终点 removed 数值误差包络|0.00000385|0.00000394|

两臂全部39次接受更新均满足代理风险上界≤0.01；每一次接受更新后，五个实际 removed KL 全部>0.01。偏差从第一槽就存在，不只是终点漂移。实际 KL 加权值与代理值的差异说明不能把代理预算解释为实际 KL 约束，但不能据此分解随机采样误差与非线性误差各占多少。

正式 `attempt(..., hard_removed=False)` 明确不启用实际 KL 拒绝。标签 `HARD_KL_NOT_ENFORCED` 正确，没有发现“已打开硬门却漏执行”的证据。HM 第8槽因 `FINITE_DUAL_REJECT` 拒绝一次；HU无槽拒绝。所有槽均无 numeric-only rejection，不能将主要失败归于 FP64 包络卡死。这里也不证明模型有限精度对极小间隔完全无影响；冻结的严格正门不放宽。

## 当前软保护没有覆盖整个外部行为

HU 的 q KL 是在 full 输入、teacher-forced 答案前缀下，排除目标 token 后的条件分布 KL；它有意把目标质量 a 从 q 分离，系数为 `1−a*≤0.05`。prefix KL 作用于同一当前源的普通语言前缀位置，排除了答案、图像位置和特殊 token。二者均不是 removed 输入上的完整词表 KL，更不是独立外部病例上的保护约束。

相对 HM，HU 终点条件 KL 从0.067786降至0.016799，prefix KL从0.208648降至0.032086，实际 removed KL从3.617273降至2.339240；说明这项政策确实改变了轨迹及这些量。HU终点 hinge 与条件/prefix 梯度余弦分别为−0.1533/−0.2719，只支持局部梯度竞争，不能证明无可行解。

外部评价却没有改善：HM与HU同样损伤固定36题中的三题，T2G同为3/4且逐题一致。HU相对旧PU修复一道T2G，但不能把该变化归因于“外部保护已成功”。Base16 是固定校准参数统计，`calibration_coverage` 仅标明8个CT/MRI源组、无KG/XRay、患者独立性未知；其低代理值不保证任意外部提示/生成轨迹不变。

因此外部失败的可证结论是“现有控制未保证并且实测未实现零损伤”。不能直接断言三题都因某个 Fisher 零空间方向、语言捷径或 removed 漂移而错；缺少匹配的外部梯度、逐槽外部输出及独立因果干预。此次不补算这些评价驱动信息，不据三道错题设计训练数据。

## 下一步为何只加 removed 软 KL

历史 SH10 已用权重1的 removed 完整词表 forward KL：10/10间隔为正，最小0.018003，但完整CE为0.519209，未达0.1且外部零损伤门仍失败。硬门 SH01 的完整CE为2.375627、20槽仅接受10次；不能默认重新加硬门就会解决问题。

冻结新臂 HR：保持 HM 的 hinge 和全部背景不变，只将 removed 软 KL 权重从0改为1。该权重沿用SH10，不依据本轮错误调参。HR−HM 是主要单因素对照；它检验在 hinge 下直接约束 removed 分布，是否能改善证据门且保住拟合。HR−SH10 可作目标形状的描述性辅助比较，不能当独立确认。

这不是已证实的修复方案：软 KL 不保证硬 KL≤0.01，也不保证逐概念正间隔，更不保证外部零损伤。若只改善间隔而仍伤三题，应如实区分源内证据控制与外部保护。先做一个新臂，不同时增加校准样本、Fisher行数、margin损失、prefix项或求解器改动。
