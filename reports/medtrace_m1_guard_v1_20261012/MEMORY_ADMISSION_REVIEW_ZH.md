# 显存峰值与准入复核

2026-10-12 用户要求核实实际峰值及必要余量后，允许显存足够的其他已授权 GPU 并行执行未开始分区。原 45 GiB 是工程准入余量，不是测得峰值；一次 nvidia-smi 读数 33564 MiB（32.8 GiB）不能代替生命周期峰值。GPU accounting 未启用，已有分区没有 PyTorch 高水位记录，不能追溯重建其峰值。

给尚未开始的正式分区加入被动记录，不额外加载模型、不重复训练/前向/反传或节点，不重启健康训练进程。记录加载后、FP32/Fisher 就绪、正式20步检查点（包含既定节点诊断）以及完成时的 PyTorch max_memory_allocated/max_memory_reserved；从进程启动以来不重置这些计数。另采样 nvidia-smi 的本进程占用与非分配器开销，采样不是连续驱动显存峰值。采样工具暂时不可用仅标记缺失，不能因此中断科学轨迹。

只有已有实际源反传、GUARD 投影及完整 BASIS/同状态诊断覆盖后的高水位，才能用于降低准入。用峰值 reserved 加至少1 GiB非分配器余量，再至少4 GiB新增分配/共享波动余量，并向上取整；考虑尚未覆盖的来源形状时保留更大余量，不能按某张卡当前空闲数倒推阈值。没有证据时仍保持45 GiB。只调硬件调度，不改八例、seed、算法、科学门槛、计数/成本、2 GiB资产/8 GiB磁盘预算；设备仍为2/3/4/7，至多三个正式训练分区。

最小检查已覆盖高水位字段、采样历史保留与 nvidia-smi 失败时记录缺失；源码语法检查通过。完整峰值仍须消费实际运行回执，不以静态估算冒充测量。

## 有证据后的限定调度修改

新增 `guard_schedule.py` 只允许在原分区0完成、分区1健康、分区2尚未创建进程，并且分区1已完成 GUARD20 同状态诊断及其后的峰值记录时使用。39 GiB准入必须仍大于 measured reserved + max(实测非分配器开销, 1 GiB) + 4 GiB；不满足则拒绝切换。固定39 GiB比最低公式另有向上余量，不自动按资源空闲或结果调参。

切换用独占一次标记，暂时暂停并复核仅等待的 CPU 调度父进程，避免重复派发；以新 CPU 调度接管等待队列，原训练子进程保持其 PID/state/RNG/RMS/计数连续，不终止、不重启。只新增未开始的分区2到GPU4，启动前再次核实UUID/显存；仍等待两活跃分区全部完成才调用原报告消费者。保留原父身份与调度切换回执，新的 SCHEDULE_START/EXIT 为后续调度权威。科学配置和累计成本不变。控制路径检查覆盖高峰值证据拒绝、只对CPU父发信号、仅启动剩余分区、完整后报告；模型峰值与阶段门槛仍以运行证据为准。

## 实际准入与启动回执

已覆盖本正式进程加载、FP32/Fisher缓存、原M1源反传、完整61 BASIS测量、GUARD投影及20步同状态诊断，随后读取的进程高水位：allocated 31.9210524559021 GiB、reserved 32.697265625 GiB；采样驱动进程占用最高33.169921875 GiB，采样非分配器开销约0.473 GiB。39 GiB准入预留1 GiB非分配器空间后，仍有5.302734375 GiB新增分配/共享波动余量，高于事先规定4 GiB。

本轮阶段A准入按用户授权从45调整为39 GiB。已完成分区0不重跑；健康分区1继续GPU7；唯一未开始分区2已在GPU4通过实时UUID/空闲显存检查后启动。原CPU调度被一次性接管，模型worker重启数0，新增训练轨迹仅原登记剩余分区；新父子进程身份与中性argv及GPU4/7绑定检查通过，无新即时失败。半小时监测沿用本会话并消费新调度回执。

这些是截至上述节点的真实PyTorch高水位与采样驱动占用，不是全部八例最终峰值，也不是连续NVML峰值；后续正式步骤继续记录峰值。共享任务后续增长仍可能消耗余量，不能保证永无OOM。没有追加用于显存验证的模型计算、改变科学门槛或增加授权设备。
