# 真实加载、系数诊断、KV 和恢复统一入口

`real_smoke.py` 已把已有生产 runtime 与诊断/生成组件接成一个入口，不再要求人工逐个调用组件。入口使用环境传入私有 manifest、输出和中性 guard 目录；必须由中性进程组启动。未运行真实模型。

执行顺序：来源/输入/资源绑定检查→独占预约→独立270秒TERM/300秒KILL guard→官方 native 加载→实际类及文件来源/transformers4.51.3/FP16层6核验→原 source/null 两个 W0 NLL→当前源 FP32 梯度→固定 rank1 诊断方向→A0 loss/系数导数核对→1e-4||W0||F 原生非零写入→cache True/False 两次官方完整生成→权重、flags、模式、hooks、generation_config 及 W0 NLL恢复→写完整RESULT。只有所有步骤正常返回才写PASS，独立KV组件PASS不足以生成资格回执。

同一预算从加载前开始，320总F、300工作F、20恢复预留、44非生成工作F、每请求128F、最多2请求、4backward上限、240工作秒/270TERM/300KILL。实际诊断计划2个梯度调用，未使用额度不是追加实验授权。vision preprocessing墙钟计入，独立视觉编码调用不伪记为全模型F。加载前48GiB空余、加载后12GiB余量、36GiB owned峰值门；实际GPU仍须外层挂载/存储/中性argv回执。原256MiB写盘界通过journal保留16MiB余量。不得修改问题、重试尺度或失败复跑。

异常保留独占预约和匿名失败类型；模型被修改后finally恢复FP16矩阵与参数flags，eval模式验证原W0损失再恢复原模式，移除本轮hook并核原hook集合。SIGTERM尝试恢复；SIGKILL及加载失败不能宣称完整恢复。只保存匿名标量和私有绑定；不保存权重、梯度、基或token。源码入口本身不自动启动两臂。
