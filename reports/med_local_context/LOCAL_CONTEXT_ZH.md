# MED 本地事实与执行条件摘要

整理日期：2026-10-31。用途：让 Pro 根据实际任务和运行证据设计方法；本摘要不是新的数据准入或实验启动门槛。本次只读已有公开报告、源码及少量文件元数据，没有读取封存问答、训练、生成或评分。下述数据均为开发集；个别记录的语义和来源独立性仍有未知。旧交接中的限制如果与本文明确标出的后续用户修订冲突，以后续修订为准。

## 一、任务和数据

MED150 是原146个编辑加4个新增开发编辑；一次编辑以图像、源问题和目标回答构成，训练中每个编辑还有4条 FIT 问法。150 是编辑数，不等同150个不同来源图像、150位患者或150个互相独立的事实。原146的 FIT 使用同一源图和目标回答；相关训练构造见 [`trajectory.py`](../../experiments/medtrace_m13_146_v1/trajectory.py)。

|角色|相对 source 的输入及目标|证据和注意事项|
|---|---|---|
|source / T0|原图、原问题及编辑目标；T0 为源编辑效果|原146按既有Base错误资格入选；不代表随机总体。|
|FIT|同源图、源目标回答的4条训练问法|是训练支持，不是独立泛化测试；轮换规则见后文。|
|T1G|换图、同问，按既有任务意图应保留同一目标|原146配对审计584/584为异图同问；图像变化不自动证明独立来源。新增4条语义支持未知。|
|T2G|同图、不同问法；原任务意图为语义保持改写并回答同一目标|原146配对审计584/584为同图异问，合格Base错误支持557；新增4条14个合格查询是构造改写。**不要称跨图泛化或自动称不同关系推导。**|
|T1L|图像局部性：通常异图同问，评价应保持相应原有回答|原146的960个结构关系中有1条问题字符串不一致，未删；最终合格支持仅1编辑2查询。不同图像内容是否构成所需语义关系不能仅从字段名证明。|
|T2L|文本局部性：同图、不同问题，评价相应原有回答应否保留|原146的98个结构关系均同图异问，最终合格Base正确支持31编辑54查询。不同问句不自动证明语义属性独立。|

结构关系数量、合格评价数量与编辑数不同；同一查询可以有多个编辑—查询消费者。实际角色由冻结任务映射、Base资格掩码及活动目标排除确定：泛化主要统计Base原错误上的修复，局部性主要统计Base原正确上的保持。FULL需要更完整的参考支持；空支持为NA，不能当作成功。任务结构和旧定义更正见 [V19 定义审计](../medmkeb_route_audit_v19_20261019/DEFINITION_AND_INVENTORY_ZH.md)；掩码及统计见 [`med133_report.py`](../../experiments/medical_proposition_v133/med133_report.py)。

原任务采用已有数据集问答及其构造的图像/问法关系；机械身份匹配或来源注释不是逐例专家独立核验。新增4条T2G是构造开发题，不能称独立确认；新增4条T1G语义未知、T2L无合格支持。原146、16编辑面板及扩展4均已用于开发或方法选择。尚无证据证明重新划分可以把这些已曝光记录变成未曝光测试；患者/研究独立性未知。M3Bench与另行构建中的MedMKEB不是同一数据划分，本次LoRA不引入后者。

## 三、实际训练、生成与评分实现

- **模型**：历史运行报告记为 LLaVA-Med / Mistral 骨干；固定层位实验的模型结构为32层、down_proj输入14336 / 输出4096。可公开的不可变模型版本未在此次摘要核验，不把显示名当权重摘要。[运行审计](../medtrace_post32_closeout_v1_20261007/SCORE_AND_INFERENCE_AUDIT_ZH.md)
- **已真实运行的C21/CDEEP**：分别为0-based第21/30层 `mlp.down_proj`，TT88 7168参数，两个新臂均未使用原MED保护曲率。两臂每编辑相同初始化、普通Adam 160步；原优化器输入/输出TT因子学习率分别1e-4/1e-3，betas=(0.9,0.999)、eps=1e-8、weight decay=0。每步为0.5 source CE + 0.5 按固定顺序轮换的FIT CE，梯度裁剪1。实现见 [`train_pair.py`](../../experiments/med_fixed_depth_v1/train_pair.py)、[`trajectory.py`](../../experiments/medtrace_m13_146_v1/trajectory.py) 和 [`paper.py`](../../experiments/medtrace_paper_transfer_v1/paper.py)。原MED另有保护曲率，不能把MED到CDEEP的全部差异归因于层位。
- **位置与精度**：训练掩码作用于预测答案的token位置，生成沿原hook的generation routing，包括首个答案预测位置；输入/多模态准备使用冻结FP16路径，随后使用FP32 decoder计算。历史固定层位记录的运行配置及RNG逐项绑定508个输入；本次新LoRA需重新验证实际位置与精度，不以源码代替实际运行。
- **生成与缓存**：已运行配置使用greedy、beam 1、最多1024新token；输入、提示、图像绑定、RNG与原运行对齐，实际 EOS/截断单列。固定深层新训练路径不使用旧 PrefixCache。可核验模型载荷与路由时才复用历史回答或分数。
- **评分**：`MEDPROP_SMALL4_CORE_FULL_SOURCE_V1`，执行记录为 `gpt-6-astra`、reasoning medium。历史原146恢复与固定层位回执 `immutable_snapshot` 均为空，不能声称模型快照一致；用户后续明确要求默认大模型评分按同一比较口径处理，因此此项不再阻止当前LoRA实验。实际模型名、配置与快照未知必须披露，不得伪造版本。
- **LoRA需要接到真实链的改动**：明确专家类型、rank/alpha、层位、状态和强度；训练与生成共用同一答案预测位置语义；接通首次编辑真实生成检查、其余15编辑、四强度冻结、评分索引/一次提交、汇总与独立守卫。当前代码是准备状态，尚未证明真实前向、参数更新、状态回载、首token或完整执行成功；不改变原训练数据、R0和旧实验。

|FIT|64/64 (64)|64/64 (64)|60/64 (56)|
|T1G|64/64 (64)|64/64 (64)|60/64 (56)|
|T2G|48/64 (45)|55/64 (55)|59/64 (54)|

T2G编辑宏平均75%、85.9375%、92.1875%；T2L编辑宏平均96.875%、83.3333%、75%，不能从30个查询直接换算编辑宏平均。C21→CDEEP在T2G修复5、损伤1，在T2L修复2、损伤6；T2L 30个Base正确项中 MED/C21/CDEEP各损伤1/6/10。CDEEP相对C21的T2G FULL宏平均下降1.5625 pp。见[固定层位结果](../med_fixed_depth_v1_20261030/RESULTS.json)、[逐项配对](../med_depth_pairwise_v1_20261031/RESULTS.json)。

本次没有导出逐编辑CSV：现有公开机器汇总只提供聚合与配对统计；安全生成逐编辑表需要额外重建身份映射及检查是否涉及私有信息，本次不为可选附件新建工程或读取封存内容。各聚合结果保持原分母，不能把宏平均与查询正确比例混用。
