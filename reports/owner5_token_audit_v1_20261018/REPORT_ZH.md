# 构造负例逐 token 损失与 Yes/No margin 补证

## 结论

本次只测同一构造负例上的原生 Base 与重建零专家 Base。两者三个预测位置的全部 32000 维 logits 逐元素相同，labels 相同；平均 NLL 均为 5.913671016693115，与历史 guard Base 完全一致。此结论仅覆盖本输入与三个 teacher-forcing 位置。

原高 NLL 并非 EOS 难以预测，而是尾部空格及小写答案 token 的损失较高。小写 no 损失不能独立代表否定判断：模型明显更偏好大写 No。大小写合并后的否定偏好为正，但优势有限。

首个答案位置 P(no)≈0.00037822、P(yes)≈0.00005349、P(No)≈0.45839108、P(Yes)≈0.33754604。No/no 概率比约 1212；合并后否定/肯定概率比约 1.359。在这四个候选内重新归一化，否定占约 57.61%，这不是临床校准置信度，也没有覆盖所有可能回答。

空格与 EOS 的总损失占 55.58%，其中几乎全是空格。EOS 概率是在已经强制给定小写 no 和空格之后测得，不能解释成自由生成时模型一定立即结束。格式损失占比不代表格式项的梯度贡献，更不能判断保护器实际挡住了哪种更新。

## 计算与校验

沿用原模型、图像预处理、prompt、FP16 输入准备、FP32 decoder、math SDPA 与 teacher routing。相同 seed 的零初始化状态与旧 BASE 状态逐张量一致，随后使用原 canonicalize 路径。原始 prompt 20 token；展开后目标位置为 595/596/597，读取 logits 位置 594/595/596，三个有效 labels 为 708/28705/2。前缀、图像特征和 padding 不计入 loss；实际展开 labels 和 attention mask 已私有保存。原始未展开 labels 明确标记为重建。

四个候选均核对为原 prompt 后的单 token。margin 仅取首个答案位置，不包含后续空格或 EOS。完整三个位置 logits 私有保存，可在 CPU 复算，无需再次前向。

同设备 GPU 逐 token 交叉熵平均与模型 loss 的差为 0，原 2e-6 校验通过。CPU FP32 重算平均差为 -3.814697265625e-6，记录而不强行追平。CPU 与 GPU reduction 的数值差异解释了早期诊断断言失败；未放宽原阈值。

## 执行异常与完整成本

共经历两次 decoder 前的工程失败：缺少显式设备授权环境变量；诊断序列化读取了旧 batch 转换后未保留的 raw_labels 属性。前者未加载模型，后者完成输入准备但 decoder 前向为 0。均保留失败回执。

随后一次原生 Base 前向因 CPU 分解误差超过阈值退出，错误地在保存 logits 前断言，导致该次 logits 丢失。修复为保留结果、分别记录 GPU 与 CPU 分解，并完整执行原两状态诊断。总计 3 次 decoder 前向，其中 2 次成功保存；输入准备中的视觉编码另计，不冒充零模型计算。零训练更新、零反向、零自由生成、零 Judge、无新增 checkpoint。最终 EXIT=0、进程已结束；可见主进程和 GPU 进程均使用中性解释器入口。

## 不能恢复的证据与解释边界

Control/Protected 终点及 active checkpoints 已在原实验按生命周期删除，逐 token logits 当时未存。本次无法拆出其历史变化，无法确定保护器实际限制的是否定判断还是回答形式，更不能证明终点 margin 得到保护。也不把一个样本的结果推广到其他问题。

本次支持的修正是：原三 token 平均 NLL 是精确短答案形式的混合指标，不宜直接命名为否定判断保护。现有 Base 结果排除了本输入上零专家改变初始 logits 的解释，并显示小写选择与尾部空格显著影响 NLL。是否修改指标或再实验留待用户决定，本次无自动下一轮。
