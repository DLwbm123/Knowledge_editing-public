# 独立 H 支持建设方案

已执行：从已批准29条train QA建立594 native的“命题—来源—答案”私有候选索引；继承完整历史保护/保留集合，并排除整个native/eval结构超集及已知hash/派生图像身份。得到2条来源标签支持的H/G，H_eval=0。没有反复重扫耗尽池。

新增来源提案：使用 **PMC Open Access Subset 中此前未在本项目暴露的医学影像图**，仅选择逐篇及逐图权利明确的 CC-BY/CC0 材料。PMC OA各条目许可并不统一，文章中第三方图可能有独立权利，必须逐图核对；这些是候选来源，不是已找到合格数据。[PMC OA说明](https://pmc.ncbi.nlm.nih.gov/tools/openftlist/)、[图像版权说明](https://pmc.ncbi.nlm.nih.gov/about/copyright/)。不采用缩小后的分类图像自动冒充QA真值。

1. 获新来源下载授权后，先建最多64个来源组的DEV候选清单（16编辑×native/train-support/H_eval/U_eval各1组的最低设计）；按文章、可识别病例/患者、研究、原图/派生图关系连通分组。来源许可/患者关系未知保留UNVERIFIED，不能直接记独立。这个上限不是覆盖保证，不足时报告缺口。
2. 图注/原文仅用于提出候选命题，不能自动生成医学否定答案。优先已锁定可审查命题（器官、模态、已明确的有/无）；原问题等价性、否定/程度/部位/时态/不确定性由医学审查者确认。
3. 每编辑最低6条来源QA：native、H_fit、G_fit、U_fit、独立H_eval、独立U_eval；native-fit四个固定包装不额外标成独立QA。H/G/U可在同一train图像上，但H_eval/U_eval必须与全部训练组隔离。G的命题不同，额外槽位及答案token长度分层匹配H。
4. DEV16最低96条QA+32个H冲突关系（native-H_fit、native-H_eval）；建议两名审查者独立审阅、分歧交第三人。最低工作量为192次QA审阅+64次关系审阅；实际不足不能伪造16。
5. DEV和确认来源先按来源连通组隔离。正式100–150仅为资源目标，最低400–600来源组、600–900条QA，独立双审1200–1800次QA+400–600次关系审阅；这些不是当前库存，也不是已授权下载数量。实际N取资格交集。
6. 新来源顺序、角色和分组先冻结，再在同一FP16环境生成Base，由获批统一Judge评分冻结Base-wrong掩码。此后不得按学生表现筛选样本。UNKNOWN患者关系、重复来源和支持复用率作为独立字段披露。

可执行准备入口：`python -m scripts.medtrace.stage18_support <旧私有source目录> <新私有输出目录> <新报告目录>`。该入口硬绑定现有授权29条，不接受新来源静默混入。新来源必须经下方审查表完整核准后生成新的版本化ledger/冻结；不要仅改数字解除检查。

待交接审查字段见 `SOURCE_REVIEW_TEMPLATE.json`。reviewer字段保持null，agent不能填通过；新来源授权/下载/人工审核尚未完成。
