实验代号：MED_FIXED_DEPTH_V1。

本次目标不是继续写可行性报告，也不是复现整套 ScopeEdit，而是回答：

在相同训练数据、TT 结构、初始化、普通优化器和训练步数下，
把 TT 专家从原 MED 的 down_proj 注入位置移到一个预先固定的深层，
是否能改善单专家 T2G，同时避免增加原知识损伤？

请以真实训练、自由生成和既有评分合同形成闭环。
权限、必要数据或执行条件确实不满足时，应明确停止并报告具体阻断，

────────────────
一、实验边界
────────────────

保留原 MED V133、M13P、全部历史结果和负结果，不覆盖、不自动替换。

本轮不做以下工作：
- 不重启第二保护方向及其来源准入。
- 不读取、恢复或间接利用存在角色冲突的旧保护缓存。
- 不重新运行 Cross-FIT 固定负结果。
- 不增加目标外 KL、前缀 KL、输入扰动或表示一致性。
- 不开发关系解析器、关系门或新路由。
- 不增加视觉投影编辑、多层联合编辑或双 TT 分支。
- 不进行层位、学习率、秩、步数或随机种子搜索。

本轮只有一个科学变量：TT 注入层位。

────────────────
二、固定三个比较对象
────────────────

M0：冻结的原 MED V133。
- 保留原权重和原生成行为。
- 优先复用绑定完全一致的原 single 输出与评分。
- 缺少匹配输出时，仅通过已有授权推理入口补充。
- 不从 M0 继续训练，不把旧 TT 权重直接搬到新层。

C21：新初始化 TT，在原 MED 的实际 down_proj 位置训练。

CDEEP：新初始化 TT，在语言骨干倒数第二个 Transformer block
的同类 down_proj 位置训练。

层位定义：
1. 从实际模型结构和原 MED hook 配置解析原注入位置。
2. 明确记录完整模块路径、0-based 索引及总层数 N，
   不根据“第21层”的自然语言描述猜索引。
3. CDEEP 固定为 0-based N-2。
4. 若 N=32，则 CDEEP 为 layers[30]，不是 layers[31]。
5. 若候选与原位置重合，或模块维度/结构不兼容，
   停止并报告，不临时换一个层追求可运行。

C21、CDEEP 均从同一个未编辑 Base 独立开始。
每个编辑完成后恢复 Base，不能累计前一个编辑的 TT 或优化器状态。

重要：
原保护曲率目前不可合法恢复，因此两条新臂都不使用它。
它们是“无原保护曲率的新训练分支”，不是原 V133 的完整复现。

CDEEP－C21 用于识别固定训练配方下的层位差异；
CDEEP－M0 用于判断候选是否值得作为原 MED 的实际升级。
不能混淆两种结论。

────────────────
三、训练配置：尽量复用现有可运行代码，只改必要位置
────────────────

共同固定：

- 同一 Base、tokenizer、图像预处理、提示模板和答案处理。
- 同一 TT88 结构、张量形状、参数数量和计算精度。
- 同一答案预测位置注入掩码。
- 每个编辑 160 次正式优化器更新。
- 每步损失：
  L = 0.5 * CE(source)
    + 0.5 * CE(FIT_j)
- FIT_j 按原四条 FIT 的原始顺序轮换。
- 每条 CE 的 token/EOS 归一化方式沿用现有明确实现。
- 不早停，不挑 checkpoint，不延长个别编辑训练。
- 两臂使用相同且预先冻结的普通优化器、学习率、
  调度、weight decay、梯度裁剪和其他 source-only 设置。

优先复用项目已经实际运行过的普通 TT source/FIT CE 训练路径。
从现有配置解析实际超参，运行前写入冻结配置文件；
不要凭记忆填写学习率。

所有依赖旧保护样本、旧曲率、逐编辑保护统计的项都必须关闭，
包括通过预条件器、动态缩放或缓存间接进入的项。
不能只删除一个名叫 protection_loss 的损失，
却仍沿用旧保护算子调整更新。

若无法把普通 CE 优化路径与旧保护路径清楚分离，
应指出具体函数和依赖，不能把“暂时关闭部分代码”称为已完成隔离。

初始化要求：
- 每个编辑使用原有预定初始化种子，不搜索新种子。
- 生成一份合法 TT 初始状态，逐张量复制给两臂。
- 使用已有的零函数、可学习初始化方式。
- 不把全部 TT 核一起清零，导致所有有效梯度消失。
- 记录两臂初始 TT 张量哈希、可训练参数名与参数数目。

本轮不对不同层的梯度或更新做额外等范数重标定。
记录更新范数和实际注入响应即可。
结论限定为“相同优化配方下的层位效应”，
不能声称已经找到各层各自的最优训练条件。

────────────────
四、缓存与梯度路径
────────────────

默认两条新臂都使用相同的完整前向路径，关闭原 PrefixCache，
避免把第21层缓存直接错误复用于深层编辑。

冻结 Base 参数不等于把全部 forward 放进 no_grad。
必须保留从 TT 注入位置经后续冻结网络到答案损失的梯度路径。

本实验不需要对输入 embedding 求梯度，
也不需要移植 ASAM 的输入梯度流程。

必须核对：
- hook 安装在指定 down_proj，而不是同名但错误的模块。
- 训练和生成使用一致的位置与注入规则。
- 禁用 TT 后恢复对应 Base 行为。
- 两臂初始零输出时恢复同一 Base。
- 实际一次更新确实改变 TT，而非只改变优化器账本。
- 保存/回载后输出一致。
- 请求结束后清理 hook 状态及 KV/cache。
- Base 权重未被修改。

若完整前向不满足资源限制，不得只给一臂开缓存、
换精度或缩短答案来继续比较。
应报告资源阻断；本轮不另建一个缓存优化项目。

候选进入后续确认，至少同时满足：
- 相对 C21 和 M0 均有实际 T2G CORE 增益，达到上述筛选门槛；
- T0/FIT 不新增原 CORE 正确事件的损伤；
- 获准保护支持中不新增原 CORE 正确事件的损伤；
- 不新增原 FULL 通过事件的丢失；
- 收益不能仅来自遗漏答案、空答或截断。

即使达到门槛，也只称“开发筛选信号”，不自动替换 MED。
若收益只来自一个编辑/来源，明确报告集中性，不称稳定改进。

分类报告：
A. CDEEP优于C21但不优于M0：
   同条件层位信号，不构成MED升级。
B. T2G提高但保护受损：
   取舍移动，不升级。
C. 两臂相近：
   当前固定层位配方无明确收益。
D. 两臂均比M0差：
   本次无原保护曲率的新分支未达到现有方法，
   不能把全部退化因果归于层位。
E. 工程、权限或预算未完成：
   记为未完成/受阻，不当成算法负结果。

不通过就结束该固定实验。
不自动换层、增加秩、修改步长、续训或添加ScopeEdit其他模块。
