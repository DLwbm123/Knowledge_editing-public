# MED 新来源训练侧元数据核查

**本轮冻结8个仅供后续来源审查的训练开发候选，不是8个已合格编辑，也不是独立确认集。** 所有统计仅基于既存数据的分区、图像组、语言、题型和qid；没有在本会话展示或用于筛选候选问题和答案，也没有读取图片像素、调用GPU/模型或下载。技术限制：代码对三个split的完整JSON做了进程内反序列化，问题和答案字符串因此进入远端进程内存；只提取图像组、语言、题型和qid，返回数据不含QA。这与预登记“不读取问题、答案”的严格措辞不符。

SLAKE train现有9,835条记录、586个图像组，其中446组至少有两个英文OPEN问题。272个train组也出现在validation或test，按预登记整组排除；再排除历史、保留、回放、V111全部15组以及MED150已知来源后，有180个组通过这次**元数据**规则，按固定组序取前8，不补位。180不是已确认未曝光或临床合格数量，8个也不保证包含两个不同谓词。原候选的图像路径尚未保存或核验，身份和qid仅私有保存。

保守排除集的去重联合为278组，其中历史快照177组、V95保留24组、V106已审8组、回放64组、V111全部15组和原MED中88个可识别的SLAKE图像组存在重叠，不能将这些数直接相加。MED原146含97个SLAKE编辑，映射到88个图像组；患者或检查独立性、跨项目/模型预训练曝光与别名完整性仍未知。PadChest/T5有历史未授权扩展约束，仅查看文件存在性，不读取或使用其内容。

第一次程序错误地将MED的通用来源字段当作SLAKE图像组，未显式列入原MED排除集；该次候选文件已保留并标记无效。在本会话未查看候选内容或模型结果后，改为从原任务既有图像路径识别全部97个SLAKE任务并重新按原规则选取。更正前后的8组元数据顺序恰好一致，是因为88个MED图像组已包含在其他排除来源的联合中；这不消除初次实现错误。两次实际枚举间隔约31秒，模型调用均为0。

这些候选的真实图像、题目语义、不同谓词、标注依据、Base错误与Base正确保护事实均**尚未审查**。后续若要使用，须先冻结单独的来源审查和模型协议；不能将其作为自动通过的独立确认数据，不能动用V95或V111保留组，也不能用测试答案反向设计方法。此次没有改变MED、M13P或既有负结果。

后续来源审查的读取方式需要先明确：不能把本轮完整JSON在内存反序列化说成没有技术读取，也不能据此认为V95/V111封存标签已获开放授权。

## 后续发现：历史CHECK32遗漏

对先前未纳入上述快照的已消费来源回放CHECK32做身份级核查后，发现固定8个候选中**2组已在历史CHECK中使用**，且两组均属于之后Base筛查的6个潜在组合。CHECK32里31组不在此前177组历史快照中，1组在其中；这说明此前“枚举过的历史无匹配”仅覆盖不完整快照，不能视为完整历史排除。原180组数字也未排除这31组，不能称为完整历史排除后的数量。初次排除和候选记录原样保留；不基于结果更换或补组。该八组本就为TRAIN_DEV，现应明确标记其中至少2组已曝光，其他组也不因此获得未曝光或患者独立证明。

本次核查只返回组身份匹配的匿名计数，未向审查者返回旧CHECK问答；实现为远端进程解析已消费开发角色JSON后只输出身份计数，并非原始QA字节从未进入进程内存。没有调用模型或修改旧输出。

同一CHECK32还与V95的24个保留组重叠1组；该组是V95的TRAIN候选，V95 DEV与CONFIRM候选在这一项对照中均为0组重叠。V111的15组与CHECK32的这次对照中为0组重叠。此发现不改变任何保留角色，也不证明V95 DEV/CONFIRM在其他历史中未曝光；已被消费的TRAIN候选不得称为新来源。原检查仅比较来源组身份，未向审查者返回这些保留组的问答。

技术边界补充：本次CHECK32身份核查在发现交集前，对既有CHECK角色JSON作了完整远端进程内反序列化。因此，其中与V95 TRAIN候选重叠的旧QA也进入了远端进程内存；这些QA未被返回给审查者、未被查看或用于选择，但不能描述为技术上完全未读取。V95 DEV/CONFIRM与该CHECK集合未发现重叠。后续不得据本次内存加载推断V95内容的开放授权；新检查必须先排除保留组并避免反序列化其QA。
