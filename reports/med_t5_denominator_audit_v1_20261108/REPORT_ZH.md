# T5 复现差异第一轮核查：分母与 Base 输出

日期：2026-11-08。起因：[Pro 对优先级的修正](https://chatgpt.com/share/6af06521-a204-83ea-bf53-b78dc61d58e4)。本轮只读取已经完成的模型输出及已经接受的 CORE 评分，没有重训、重新生成、重新 Judge、恢复 UNKNOWN 或改动名单。下面不把公开仓库的 ΔACC 当成已经确认的作者表格指标。

## 结论先行

1. **本地高随访准确率与很差的既有正确答案保持能力同时存在。** 旧最终库中四种方法现在均完成评分，都是143个错→对、1个对→错：随访准确率99.31%，但预正确任务保持率0/1。单纯对比99%与作者的Temporality会混淆不同量。
2. **Base 的低分主要不是空答或截断造成的。** 筛选前322个随访回答中307个以No开头、15个以Yes开头，全部EOS正常结束、0个达到长度上限。筛选后的159个随访回答为158个No开头、1个Yes开头。这里是原始回答形式统计，不是给UNKNOWN重新打标签。
3. **新159例也没有出现超过恒答Yes的已确认优势。** 已完成本地评分的MDU与LoRA最终库均为155/159正确，四个10任务均错误；单次LoRA另保留1个评分UNKNOWN。修正分母后高分依旧，不能宣称时序变化能力。
4. **作者0.42–0.66为何分散仍未定位。** 现在可以具体描述本地输出与计分行为，但不能确定作者实际使用了哪个分母，也不能由作者方法有分差推导其恒答Yes控制一定低于90%。

### 为什么旧99.31%也可以对应保持率0%

旧bank的分母是：全部任务144，其中Base随访原正确只有1个，原错误143个。三个相互不同的量是：

- 随访准确率：`143/144 = 99.31%`。
- 旧本地主指标：`1 - 1/144 = 99.31%`。
- 已知原正确答案保持率：`1 - 1/1 = 0%`。

这证明不同分母足以造成巨大表面差异，**不证明作者用的是第三个公式，也不能选择某个更接近作者数值的公式作为“复现成功”**。对新159，预正确成员还有11个UNKNOWN，0/1仅是已知预正确子集，不冒充完整保持率。

旧bank的唯一已知预正确随访参考为No，143个预错误参考均为Yes。因此，“总体Yes很多”与“应保护的已知正确任务恰好是No”在本地确实同时成立。总标签分布不能代替条件子集分布。

其他否定句是明确表示没有病征的句式；不是拒答。自动形式分类对所有644条均有覆盖，没有剩余OTHER或可疑拒答类。该分类不评估整句医学真值，也不改变CORE结果。

说明：

- 在资格筛选前，强No倾向就已存在。因此它不完全由“仅保留既往错误”筛选创造；该筛选会进一步集中此前持续否定阳性病征的任务。
- 322个随访任务中，有39种问题对应多个不同影像；其中37种问题在这些影像上的Base回答文字完全一致。既往侧为35/39；筛选后随访为18/20。包含只有一张影像的问题会夸大这种一致性，因此这里只统计多影像问题。
- 文字一致说明输出区分度低，**不能单凭此证明模型没有读图、缓存串图或图像预处理错误**。实际相似图像也可能产生相同回答。还缺少独立的图像条件干预或官方推理路径对照。
- 四种旧方法的single与bank全部随访回答均以Yes开头，且各自既有CORE分数一致。MDU与LoRA新159的single与bank也全部以Yes开头；LoRA single的一个评分UNKNOWN仍为UNKNOWN，未以Yes前缀替代评分。

因此，本地已经观察到“Base偏No、编辑后偏Yes”的模式，而不是“Base大量空答，编辑后终于正常输出”的模式。其原因仍可能涉及模型本身、问题模板、视觉输入／精度路径或编辑适配，尚未做因果归因。

## 3. 对简单工程解释的有限核对

读取实际Base输出记录与生成源码得到：

- 644条Base输出均记录实际float32推理，`prediction_reused=False`；不能用“按问题复用了同一缓存答案”直接解释这644条重复文字。
- [Base生成代码](../../experiments/med_t5_core_v1/base.py) 的预测缓存键包括准备输入的完整绑定，不只是问题；已有输入绑定包括影像身份与实际prompt。这个静态事实不等于全面排除了上游视觉输入错误。
- 冻结生成合同记录贪心解码、`max_new_tokens=1024`、`mistral_instruct`，未把目标答案放入提示、未用teacher forcing、未按参考长度截断。EOS和长度计数与正常短回答相符。
- [预处理源码](../../experiments/med_t5_core_v1/preprocess.py) 将16位灰度图逐图min/max映射为8位RGB，生成时保持既有FP16多模态准备与FP32 decoder路径。这些是本地固定实现，作者实际T5运行的预处理／精度合同尚未确认一致，不能因本地方法共享同一实现就宣布作者级复现已验证。
- [34条源审查](../med_t5_change_audit_v1_20261108/REPORT_ZH.md) 已确认一条CT比较对象问题、三条确定性丢失等风险。它们应单独记录，但不能单独解释所有方法从No变Yes或几十个百分点的差距。

本轮未新跑模型、未另开图像干预或标准推理对照，现有冻结实验不受影响。

## 4. 对作者Temporality的解释边界

[论文表2](https://arxiv.org/html/2607.05310v1) 给出LLaVA-Med的Temporality分数：MEND单次/连续0.53/0.48，GRACE0.66/0.55，BE0.55/0.45，LoRA0.42/0.58。这里保留Temporality名称，不把这些数值改称为随访准确率或ΔACC。

[固定公开仓库](https://github.com/BioMed-AI-Lab-U-Michgan/M3Bench/tree/03c6fda3813301dab3be5831fdc94b493c10afc9/tasks/T5_temporal_delta_acc) 则定义ΔACC，README仍称T5尚未运行。两者并不能证明作者表格实际用了什么分母。本地源池、Base资格、推理合同、Judge合同、编辑器状态组织也尚未全部与作者执行材料逐项对齐。

因此：

- 可以确认本地总体准确率的多数答案捷径与保持能力失败。
- 不可以确认原作者队列上的恒答Yes准确率、原作者保持率或实际ΔACC。
- 不可以因为作者方法分数分散，就推断其源数据必然均衡；训练后的实际编辑器不一定采用恒答策略。
- 不可以因为本地恒答策略很强，就断言作者T5一定没有鉴别力。
