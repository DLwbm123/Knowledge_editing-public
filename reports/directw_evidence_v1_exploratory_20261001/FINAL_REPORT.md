# Completed eight-case exploratory pilot

E1 plus its E2 continuation completed all eight independent original-training cases. Final accepted edits: **0/8**. Five cases ended BACKTRACK_REJECTED; three ended NOT_SATISFIED at the frozen three-step limit. All transactions restored the original Base exactly according to native receipts. No successfully edited matrix existed for new clean export/reload evaluation; that consumer remains unexercised in this pilot.

E1's four completed negative cases were carried forward unchanged. Its fifth-case OOM was retained as an interrupted attempt and retried in E2 with the same data, method, thresholds and budget. E2 completed the remaining four without another error. The actual E2 process had exited at inspection (2026-10-01 13:15 China time). No formal evaluation or paid Judge was used.

Both runs' preliminary native mechanical checks passed their implemented parity/GGN checks, while their attempted mechanical edit was rejected and rolled back. This is not evidence of edit effectiveness. All eight cases had zero same-precision functional/native logit difference. Cross-precision FP32/BF16 maximum logit differences were approximately 0.308–0.439. Several cases made real BF16 score improvements before stopping short; intermediate improvements are not counted as accepted edits. First-step and later BF16 rounding zeroed a large fraction of proposed matrix components. Some candidates also violated the fixed reference KL ceiling of 0.001. These observations suggest multiple possible bottlenecks rather than a demonstrated single cause.

The complete sanitized receipts, including actual per-case scores, reference-budget diagnostics and all eight statuses, are in [FINAL_RESULTS.json](FINAL_RESULTS.json). E1 ran 845.749871 seconds and E2 ran 860.448244 seconds; historical cumulative native process time is 1850.591329 seconds (about 30.84 minutes), including earlier smoke runs. E2 used 143 new GGN calls; historical cumulative calls are 304, including the failed OOM call. No experiment count or budget was reset on resume. Peak case PyTorch allocation was about 57.90 GiB.

Scope remains EXPLORATORY_TRAINING_ONLY. The eight examples overlap development and editing support, references have unknown medical scope, visual positive/negative pairs and independent calibration are unavailable, and original scientific admission remains BLOCKED_DATA. This negative result does not estimate clinical or held-out efficacy.

## Follow-up rationale

The shared solver linearizes FP32 functional scores but accepts steps using normal BF16 scores. A difference in the local score value therefore changes the right-hand side of the QP even when deployment is still short of the target. The next separately frozen experiment will test a native-value-anchored affine constraint (BF16 current value, FP32 Jacobian), retaining the existing protection term, exact GGN, three-step budget, target gain, KL ceiling, trust/drift limits and actual BF16 acceptance. All eight development cases will be reused, with the completed historical run as control and initial native scores checked for parity. This is an explicitly exploratory algorithm ablation, not a retroactive repair or relaxation of the completed experiment.
