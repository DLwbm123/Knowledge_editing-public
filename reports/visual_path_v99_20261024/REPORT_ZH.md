# V99 诊断结论：视觉链路有效，当前任务的辨别仍不足

**本轮证据更支持当前冻结 Base 在这些病例与问法上的辨别不足。没有发现“图片未进入模型”或“视觉特征没有传给语言模型”的证据。** 图像内容能够改变内部特征、首 token 分布，去掉图像还改变了结节问题的回答方向；但原图与相反来源的换图都未得到正确的阳性/阴性区分。

三条路径均已执行，包括官方固定 Transformers 4.36.2、没有项目 forward 兼容补丁的独立进程。不能将这项局部诊断推广为模型在所有医学任务上无能力，也没有方法训练或方法有效性结论。

## 冻结矩阵与实际结果

协议 `81a39598` 在模型调用前推送。固定气胸、肺实变、肺结节、肺浸润各一对，共 8 名患者；来自已经知道失败的 V98 面板，属于诊断，不是独立确认集。

原图、配对换图、无图三条件在 C/N/R 三路径上比较。相同问题的换图就是配对另一例的原图输入，两例无图输入也相同，因此预先合并为 36 次实际生成、72 个条件消费者。不能把消费者数当作独立样本数。

| 路径 | 阳性正确 | 阴性正确 | 有图事实正确 | 无图的事实方向 |
|---|---:|---:|---:|---|
| C：当前 FP16 前缀＋FP32 解码、4.51.3 兼容层 | 0/4 | 4/4 | 4/8 | 三类回答无发现，结节回答有发现 |
| N：当前环境官方原生 FP16 调用 | 0/4 | 4/4 | 4/8 | 同上 |
| R：官方固定 4.36.2 API、原生 FP16、无兼容补丁 | 0/4 | 4/4 | 4/8 | 同上 |

三路径的有图答案均否认对应发现。C 与 V98 的 8 个原始 token 序列完全复现。C/N 的 12 个独立输出有 11 个全文一致、12 个事实方向一致；N/R 全部 12 个全文一致。版本核对没有恢复这四类阳性病例的辨别。

无图的结节回答还编出了具体图像细节，不能计为临床正确。其诊断作用是：同一道结节问题，有图时回答 No，无图时回答 Yes，说明图像条件确实影响了生成行为。

## 视觉链路的直接证据

- 三路径的全部 24 个有图生成均实际调用视觉塔和投影器各 1 次；图像占位符为 1，投影特征完整注入语言模型首轮输入，逐元素最大差值为 **0**。无图的 12 次生成均为 0 次视觉调用、0 个图像占位符。
- 8 张图像的处理张量与特征均有限。配对换图的像素张量相对 L2 差异约 0.67–1.23；投影特征相对 L2 差异约 1.12–1.19。因此不是不同文件被读成相同图像或相同视觉特征。
- C 路径换图使首 token 概率分布的总变差距离达到约 0.020–0.072；有图与无图约 0.134–0.234。它们并非完全相同计算，尽管换图后首 token 的最优类别未变。N/R 出现相近现象。

这些证据支持“视觉信息进入并影响计算，但未转化为正确的病变辨别”。它们不证明影像表征足以支持临床判断，也不区分训练不足、视觉分辨率限制、分布迁移、提示适配和模型融合机制等更深原因。

## 核对官方路径时发现的差异

固定官方提交为 `30697ca50b5c29a8e955c99330b259776aef27b9`，核对了 [model_vqa.py](https://github.com/microsoft/LLaVA-Med/blob/30697ca50b5c29a8e955c99330b259776aef27b9/llava/eval/model_vqa.py)、[mm_utils.py](https://github.com/microsoft/LLaVA-Med/blob/30697ca50b5c29a8e955c99330b259776aef27b9/llava/mm_utils.py) 与 [pyproject.toml](https://github.com/microsoft/LLaVA-Med/blob/30697ca50b5c29a8e955c99330b259776aef27b9/pyproject.toml)。使用官方 mistral_instruct 模板、process_images、模型加载器和 generate。

发现官方 `expand2square` 会随机选择相邻的两个整数补边位置，造成 1 像素偏移。C 按图像固定种子，N/R 的原生补边抽样不同：N 与 C 有 4/8 个像素张量完全一致，R 与 C 为 6/8。随后仅用 CPU 对齐同一图像种子，在官方固定版本下 **8/8 像素张量完全一致**。这解释了预处理差异，原始生成结果保留，没有用后来对齐的张量重新生成。

N/R 是官方原生 API 路径核对，并非作者完整 benchmark 脚本和全部环境的逐项复现：其生成没有复刻官方脚本的全局 seed=0 补边序列，当前 Torch 2.7.1/CUDA 为服务器兼容版本。固定版本进程使用 Transformers 4.36.2、tokenizers 0.15.2，未安装项目 forward 兼容补丁。原生随机补边与精度/版本因素没有在生成中完全解耦，因此不能把微小 logits 差异单独归因于某一项。三路径事实判断均未改变，也没有证据证明这 1 像素差异造成了“全部否认阳性”。

## 工程事件、预算与交付

保留两项工程事件：启动器在依赖安装完成前检查回执，导致阶段衔接提前退出；随后参考加载器传入 cuda:0，使旧 API 触发 device_map 与 low_cpu_mem_usage=False 冲突。后一事件发生在 0 次模型 forward、0 次生成时，改为官方默认 cuda 后执行尚未开始的参考路径。C/N 结果未重跑，失败回执、时间和费用全部保留，原始时钟未重置。

实际共 **36 次生成、718 次 forward、0 backward、0 更新、0 教师/judge**；所有回答到 EOS，没有截断或重复生成。GPU 进程合计 **100.43 秒**，包含失败加载进程；36 次完整答案均已阅读。独立资源守护正常结束，无超预算触发。只安装两个轻量版本包，下载约 11.8 MB，未复制或下载模型权重，未修改共享环境和官方代码。

原始影像、患者标识、完整回答、首 logits 和运行路径保持私有。公开诊断代码、协议、聚合结果和本报告；没有训练 checkpoint、没有继续后台训练或空监测。

## 对后续工作的影响

V98 的阴性保护正确不能升级为可靠的患者特异性知识证据。本轮也不支持通过修复“没有传入图像”来恢复这批任务，因为该环节已通过直接检查。

因此，后继若继续研究患者特异性纠错与保护，应优先解决当前模型与影像事实任务的能力适配，并用能够辨别阳性/阴性的检查作为准入；继续从同类阴性回答中凑保护样本，不能解决此瓶颈。是否更换模型、调整任务或进行主线适配，应另立有限协议，不能把本轮局部诊断当作训练收益或全模型能力上限的证明。
