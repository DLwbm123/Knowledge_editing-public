# V99 冻结诊断：原图、换图、无图与官方推理路径

本轮由用户明确要求诊断视觉输入链路与 Base 辨别能力，所有选择先于本轮模型调用。V97/V98 保持原结果，不训练编辑方法，不更换病例直到获得阳性结果。

## 固定病例和输入

从 V98 来源已准入配对中，按既有顺序取每类保护发现首对：气胸、肺实变、肺结节、肺浸润，共 4 对、8 名患者。仅使用既有正向存在性问题，不增加提示或答案示例。这是看过 V98 失败后设计的诊断面板，不是独立确认集。

每个病例三条件：原图；替换为同问题的相反来源配对图；无图。无图条件删除图像占位符并令 images=None，不用黑图冒充无图；它是干预诊断，不按患者真值计准确率。

同一配对的两例问题完全相同，因此一个病例的换图输入等于另一个病例的原图输入；两例无图输入也相同。预先合并这些完全相同的输入：每条路径 8 个有图＋4 个无图独立生成，代表 24 个病例条件。三条路径共 **36 次生成、72 个条件消费者**。只按实际 36 次计费用，不将复用消费者当独立样本。

## 三条路径

- **C 当前路径**：现有官方模型加载器、Transformers 4.51.3 兼容补丁，FP16 多模态前缀后以 FP32 解码；重新生成 8 个有图答案，核对 V98 原始 token。
- **N 当前环境官方原生路径**：相同冻结权重，使用已核对的官方 model_vqa.py 的对话模板、process_images 和 model.generate，原生 FP16，不使用前缀替换。仍需当前环境兼容补丁，因此不能称为独立旧版本验证。
- **R 官方版本 API 路径**：独立进程中固定 Transformers 4.36.2、tokenizers 0.15.2，使用同一官方加载器、模板、预处理和原生 FP16 generate，不安装项目 forward 兼容补丁。只隔离这两个轻量包，Torch/CUDA 保持服务器兼容版本，不宣称完整复建 2024 年全部环境。

官方源代码固定在既有 LLaVA-Med 提交 30697ca50b5c29a8e955c99330b259776aef27b9。已核对官方 README 指定 mistral_instruct，pyproject 指定 Transformers 4.36.2；model_vqa.py 使用 process_images、半精度图像张量和 model.generate。允许的本地适配仅为共享离线视觉权重路径、GPU 选择、确定性参数和记录钩子。原始共享源代码与权重不修改。

若 R 的依赖或 API 无法运行，记录为参考路径未验证，不能把 C/N 一致当作已排除版本问题。包安装失败不得自动扩大环境重建或下载权重。

## 必须记录的证据

1. 图像路径与问题绑定、处理后张量形状/有限性、正负配对像素张量差异；C/N/R 的提示 token 与处理张量是否一致。
2. 视觉塔和投影器实际调用数，特征有限性、形状、范数及配对特征差异。
3. 图像占位符数量、语言模型首轮实际 inputs_embeds 长度；视觉块是否与投影器输出一致。无图应没有图像占位符、视觉塔/投影器调用及视觉 token。
4. 首 token 完整 logits、图像间/无图间分布差异与最大差值、完整生成 token/EOS；按全部回答判读事实方向。
5. C 与 V98 的 8 个有图输出复现率；C/N/R 的输出、首 logits 和临床事实判读差异。精度导致的微小数值差异与事实翻转分开报告。

所有钩子只读观察，不替换模型数据；C 的既有前缀替换是待诊断路径本身，N/R 不使用它。完整矩阵结束后统一判读，不按中途结果改路线。

## 判定规则

- 张量错绑、图像特征未产生/非有限、视觉块未注入或无图仍调用视觉链路：工程链路证据，先定位具体阶段。
- C/N/R 提示或像素张量不一致，或官方路径与当前路径出现事实答案差异：记录具体路径差异，不能直接归因模型能力。R 不可用时保留版本不确定性。
- 输入链路证据通过，三路径均无法辨别本面板阳性/阴性：支持当前冻结模型在这批病例与问法上辨别不足；不推广到所有影像任务。
- 换图/无图改变特征或 logits，但不改变回答：说明视觉信息可能进入并影响计算，输出仍受相同答案偏向主导；不能据此说图像完全未参与。
- 只有正确官方路径恢复辨别，才将相应差异作为当前链路问题的直接证据；本轮不自动重跑 V97/V98 或改写历史结果。
