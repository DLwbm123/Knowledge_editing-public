# T5 数据偏斜与评测有效性：供 Pro 独立分析的证据报告

日期：2026-11-08。运行快照：北京时间 18:11:29。本文为诊断与审阅材料，不是修正版最终结果，也不授权执行文中的候选路线。

## 1. 需要 Pro 判断的问题

用户希望论文采用所选 MDU 方法、统一 CORE 判定，并取得可信的标准方法对比。当前 T5 的关键问题是：**不利用随访影像、恒答 Yes 的解析控制已有 97.48% 准确率；更换为公开仓库的 ΔACC 之后，这个控制依然可能得到很大的正增益。** 因此，即使 MDU 和其他方法取得高分，也不足以证明它们理解了疾病随时间的变化。

请优先判断：这个数据池还能支持什么论文结论；是否应把现有 T5 降为有明确限制的补充结果；怎样用最低必要成本区分“参考答案／源数据问题”“评分缺失导致的资格偏差”和“模型仅迁移 Yes 答案”。不应以降低对比方法表现或按已观察到的效果重选样本来制造主方法优势。

## 2. 证据范围与上游口径

原论文 [arXiv:2607.05310v1](https://arxiv.org/html/2607.05310v1) 的 §3.2、附录 A.4/A.5 以既往影像编辑、同患者随访影像测试定义 T5；其进展映射为：stable/improving/worsening→11，new→01，resolved→10。论文给出 324 实例、440 影像、43 疾病，并用“避免引入随访事实错误”的文字描述指标，没有明确到足以唯一恢复实际 T5 分母的公式。

本次实际核对的公开仓库固定于 `03c6fda3813301dab3be5831fdc94b493c10afc9`，提交日期 2026-06-28，早于论文日期。其 [T5 配置](https://github.com/BioMed-AI-Lab-U-Michgan/M3Bench/blob/03c6fda3813301dab3be5831fdc94b493c10afc9/tasks/T5_temporal_delta_acc/task_config.yaml) 明确：仅 T1 错误入组；T2 同患者、同问题；主指标为 `ACC_after(T2) - ACC_before(T2)`，同时报告前后准确率，允许 fuzzy 或 LLM 判定。

但该提交的 [T5 README](https://github.com/BioMed-AI-Lab-U-Michgan/M3Bench/blob/03c6fda3813301dab3be5831fdc94b493c10afc9/tasks/T5_temporal_delta_acc/README.md) 仍说明尚未运行 T5；实际仓库树没有 T5 构建器、执行计分器、作者实例清单或已处理的 PadChest-GR 元数据。因此这里只能称“公开发布规范对齐、同 CORE 判定的本地 DEV”，不能称为作者论文表格的精确复现，亦不能直接比较排名。上游文字规范与作者实际实验是否一致仍未知。

## 3. 数据从哪里偏了

### 3.1 筛选前已经极度偏向随访阳性

源元数据有 324 个进展行；两个同影像对／病征／二值标签的冗余行合并，保留原行绑定，得到 322 个 canonical 任务。涉及 212 个患者组、220 个影像对、435 张影像、67 个原始标签。这里的“例”是任务，不是独立患者。来源划分为 train 228、validation 24、test 70；当前合并使用作 DEV，不冒充独立测试集。

| 阶段 | 任务数 | 11：持续存在 | 01：新出现 | 10：已消退 | 随访 Yes / No | 恒答 Yes 准确率 |
|---|---:|---:|---:|---:|---:|---:|
| canonical 源池 | 322 | 288 | 28 | 6 | 316 / 6 | 98.14% |
| 旧版：既往错且随访评分已知 | 148 | 147 | 0 | 1 | 147 / 1 | 99.32% |
| 旧版：再加全局影像角色安全门的最终库 | 144 | 143 | 0 | 1 | 143 / 1 | 99.31% |
| 修正版：仅既往明确错误，single 和 bank 同名单 | 159 | 155 | 0 | 4 | 155 / 4 | 97.48% |

**偏斜首先存在于源池，不能全部归咎于后续 Base 筛选。** 修正版的 Yes 比例甚至略低于源池，但“发生状态变化”的 01+10 支持由 34/322=10.56% 降到 4/159=2.52%，时序变化覆盖进一步不足。

stable/improving/worsening 映射为 11 与论文一致，但这种二值存在性问题不会测试其严重程度改变。全源池也只有 6 个随访 No，无法靠重新加权创造更多独立消退病例。是否存在源标注提取／配对遗漏，仍值得核对；目前没有证据允许把它当作已确认错误。

### 3.2 Base 资格缺失与筛选链

| 二值代码 | 既往明确错、随访已知 | 既往明确错、随访未知 | 既往评分未知 | 既往明确对 | 总计 |
|---|---:|---:|---:|---:|---:|
| 11 | 147 | 8 | 133 | 0 | 288 |
| 01 | 0 | 0 | 19 | 9 | 28 |
| 10 | 1 | 3 | 2 | 0 | 6 |
| 合计 | 148 | 11 | 154 | 9 | 322 |

当前 159 例全部既往参考答案为 Yes，且已确认 Base 错。28 个 new/01 中，9 个因既往回答正确而按规范不入组；其余 19 个资格未知，不应断言全部不合格或全部合格。**没有 01 不是“源池没有新出现病例”，也不是已证明 Base 能正确回答所有此类问题。**

154/322=47.83% 的任务资格仍未知。Base 评分队列的独特 payload 计数为 40 个有效、52 个 UNKNOWN；一个 payload 可绑定多个任务，不能把 154 当成 154 次独立 API 失败。本报告未逐条追溯全部 UNKNOWN 原因，因此不把缺失机制统一归为网络失败，也不假定随机缺失。已接受标签、失败记录和固定名单均未重写。

### 3.3 补齐资格不能单独解决偏斜：可证明的界限

在“保留已确认 159 例、只从现有 154 个未知资格任务中增加真正既往错误任务、参考标签不变”的条件下，未知任务只有 2 个 10、133 个 11、19 个 01。要把恒答 Yes 的准确率压到最低，只能加入那两个 10，而不加入任何随访 Yes：

`最低恒答 Yes 准确率 = 155 / (159 + 2) = 96.27%`。

若假设全部 154 个未知都最终入组，则为 `307/313=98.08%`。这是条件推导，不是实际补评分结果。因此恢复评分可以改善资格完整性与缺失偏差判断，却不能让这个源池自动成为均衡的时序测试。

## 4. 指标问题：修正 ΔACC 仍不能排除答案捷径

旧主指标为 `1 - count(Base随访正确且编辑后错误) / 全部编辑`。旧 144 例仅 1 个随访 Base 正确，故无论编辑后怎样回答，旧主指标都至少 143/144=99.31%。不编辑的 Base 旧主指标为 100%，但随访准确率只有 1/144=0.69%。旧主指标在本队列上几乎没有鉴别力，不能继续作为主要时序能力证据。

修正版以公开规范的 `ΔACC = ACC_after - ACC_before` 为主指标，固定 159 分母。随访 Base 已知正确 1、已知错误 147、未知 11，因此：

- Base 随访准确率范围为 0.63–7.55%；这是未知标签界限，不是置信区间。
- 恒答 Yes 的解析准确率为 97.48%，故其 ΔACC 本身也可达 **+89.94 至 +96.86 个百分点**。
- 不编辑 Base 的配对 ΔACC 恒为 0；相同未知标签在前后是同一事件，不能把“不编辑”算成虚假的非零范围。
- 方法相对恒答 Yes 的 ΔACC 优势，等于两者编辑后准确率之差：共享的 Base 项完全抵消。仅展示很大的 ΔACC 并不能证明超过这个捷径。
- 当前所有既往编辑参考答案都是 Yes，“把既往正确标签直接复制到随访”与恒答 Yes 在这 159 例上完全等价，不能用它区分是否理解时间变化。

这里的恒答控制是按既有二值参考标签计算的解析控制，尚未把字面字符串 `Yes` 重新送 Judge；不能冒充实际模型生成或新的 CORE 调用。对已接受模型评分与参考二值解析的不一致，若存在，应单独审查。

## 5. 已有模型证据与当前运行状态

旧 144 例最终库：MDU、BalancEdit、LoRA 的 144 个回答均以 Yes 开头；三者既有 CORE 随访准确率均为 143/144=99.31%，且都答错唯一的随访 Base 预正确任务，Retention 为 0/1。三者与恒答 Yes 的准确率相同，没有观测到高于该解析控制的优势。**回答前缀不能单独证明模型完全没有利用影像**；尚未做影像替换、遮蔽或其他因果诊断。

仅将旧名单离线改算 ΔACC，三者都是 +98.61pp；这依旧与恒答控制匹配，不能冒充修正版 159 例的新结果。旧 single 的结果也没有被用作实际 final-bank 结果。

修正版运行快照（18:11:29，仅状态，不是最终评价）：MDU 已完成新增 11 个专家中的 5 个，正在训练第 6 个；原有 148 个专家只读复用。LoRA 的 159 例 single 输出完成，bank 已加入 100/159 个编辑。GRACE、BalancEdit 尚在队列。最终修正版 CORE 指标未产生。初始路径配置导致的模型加载前零编辑退出已单独记录；修复未重置时钟、未重启 MDU，也未改变科学配方。

本报告只做离线聚合与写作，新增模型调用、Judge 调用均为 0。现有冻结实验继续按原预算运行；“请 Pro 分析”不解释为停止、重启、恢复历史评分或另启新实验。选定的 MDU150 主结果与 CORE 判定口径保持原记录。

## 6. 其他会影响论证的局限

1. **作者队列不能精确恢复。** 本地 322/435/67 与论文 324/440/43 不同；去重映射已保存，作者病例清单和标签映射缺失。不能为对齐数字随意拆分、补标或改疾病分类。
2. **纵向配对证据有限。** 220 对中，19 对有双方日期／患者元数据独立交叉验证，其余 201 对依赖源数据显式 PreviousStudy/PreviousImage 关系。缺少的既往日期保留空值，不补造。正确标识方向与两次问答绑定仍是可审查的代码问题。
3. **存在共享影像和相关性。** 修正版取消了本地额外的全局影像角色排除门；有些影像可能作为其他任务的既往编辑图像出现。不能宣称所有随访影像从未被编辑使用；任务数不能当独立样本量，未来不确定性估计应考虑患者／影像对聚类。
4. **技术适配与作者实现不是同一物。** 当前为匹配的多模态预处理与实际 FP32 decoder、固定解码及 CORE 合同；对比方法配置有公开适配记录。MEND 缺来源和骨干均匹配的已训练编辑器，未填分数。不能借作者表格补齐本地缺项。

## 7. 给 Pro 的判断选项与限制

以下是待评估方案，不是已经选定或获准执行的新实验：

| 选项 | 能解决什么 | 不能解决什么／代价 |
|---|---|---|
| 保留发布规范微平均结果，并加恒答控制、11/01/10 分层、No 类召回和相对控制差值 | 如实显示真实分布下的高分和捷径，成本最低 | 4 个 10、0 个 01 的证据仍很弱；不能变成强时序结论 |
| 在同一固定名单上增报 balanced accuracy 或已观测 transition 宏平均 | 降低155个11对均值的支配；恒答Yes的两类balanced accuracy为50% | 不是原始发布主指标；4个No仍不稳定，缺失01不能补零或假装存在；不创造新病例 |
| 单独审查并在新协议中恢复既往资格 UNKNOWN | 明确入组完整性、缺失原因，可能恢复部分01 | 需要处理既有失败的重试边界；上述96.27%界限证明它单独不能消除源偏斜 |
| 先做源标注／方向／问题语义的有限人工或代码审查 | 可发现真正的数据构造错误，而非把标签分布当错误 | 没发现错误就不能改标签；需区分源证据与推断，不因期待性能差异改数据 |
| 另立独立的变化敏感诊断队列或增加真实纵向病例 | 可能增加01/10覆盖、区分标签复制与影像条件判断 | 新数据访问、标注与新 estimand；不能从已暴露结果中挑选“更好看”的病例，也不能继续叫作者同队列复现 |
| 将现有T5作为有限诊断／补充，暂不用于强主张或跨论文Overall | 避免用无鉴别力高分支撑主结论 | 论文对时间泛化的结论必须相应缩小；其他任务好坏也须原样呈现 |

任何重采样／重加权都应声明改变了哪个目标总体；增加反向配对或改成进展问答也会改变任务定义，不能直接替代既往→随访存在性编辑。不得拿修正后方法的结果选择重采样比例或调优参数。
