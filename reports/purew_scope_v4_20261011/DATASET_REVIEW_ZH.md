# M3Bench 与 MedMKEB：数据需求和第四轮边界更正

核对日期：2026-10-11。已读取论文全文对应构造/指标章节、当前作者发布的任务定义与数据文件，并检查当前 pro5000 的预期数据目录。GitHub 请求全部使用显式有效代理；没有训练、生成、评分或接受数据访问条款。

## 必须更正的启动条件

不必须另找数据，也不必须先有 24 个新编辑、每编辑两个额外跨图训练锚点。那些是上一份草案提出的更强验证设计，不是纯 W、C/U/H 或原 benchmark 的必要条件。来源绑定和训练/评价角色合法仍是必需条件；新临床或独立病例结论仍需相应证据。

本轮 H 指过去已准入编辑监督的历史回放，可以来自已写入的源请求及已经声明的训练锚点；它不天然需要一个额外独立 H 数据集。这不同于历史 Stage15/16 对外部独立事实支持 H 的资格要求。不得把那一历史 unsupported 结论直接移用为本轮历史回放不能执行。

T0 原始编辑请求可以提供训练监督，这是知识编辑任务本身。未训练 T1G/T2G、locality 和保护探针的错误不能转成训练标签，也不能根据七个失败设计训练改写。两类“错误题”的角色不同，不能混为一谈。

## M3Bench

- 论文报告 16,276 个问题，支持单编辑与连续编辑；T2G 明确为**同一图像上的等义文本变体**，因此本次审查的 28/32 同图不是构造错误。七个失败不能据此归因跨病例传播。
- 论文 T1G 包括语义匹配的不同患者图像；当前公开 TASK_DEFINITIONS 和 T1G builder 的具体实现是 blur/crop/contrast/noise。作者 task builder 不执行编辑模型或 VLM 推理。不能把 release 的增强图结果冒充患者间迁移，也不能称完整复现论文。
- 底层医学数据要按原来源取得，当前作者仓库没有打包原始图片。论文还包含跨模态/组合/时间维度，公开实现与论文之间的范围差异须继续列出。
- 本研究已有来源绑定的 VQA-RAD/SLAKE、前三轮八编辑和合法训练锚点。先前审查的 268 条/74 图通过原始标注与角色筛查，它们不是“医学标签无效”。只是尚未组成草案所要求的更强独立跨图包；该包不能继续被当作基础机制实验的硬启动条件。

适合本轮主对照：真实来源答案修复、连续写入保持、T2G 文本泛化、release T1G 图像扰动与 locality。若报告真正跨病例泛化，应另用来源已证实的匹配病例面板，而非改变 T2G 的定义。

来源：[论文](https://arxiv.org/html/2607.05310v1)、[作者仓库](https://github.com/BioMed-AI-Lab-U-Michgan/M3Bench)、[任务定义](https://github.com/BioMed-AI-Lab-U-Michgan/M3Bench/blob/main/TASK_DEFINITIONS.md)、[T1G 代码](https://github.com/BioMed-AI-Lab-U-Michgan/M3Bench/blob/main/tasks/T1G_same_question_same_semantic_image/build_task.py)。历史固定 release 的差异记录另见 m3bench_reproduction/REPRODUCTION_AUDIT.md。

## MedMKEB（用户所称 MedKEB 的对应检索结果）

- AAAI 2026 论文支持单编辑、连续编辑，包含文本改写、同医学实体图像替换、locality、多跳 portability 和攻击 robustness。
- 这是**反事实编辑 benchmark**：将原答案实体替换为另一实体作为编辑目标。成功意味着命中指定目标，不自动意味着修复真实医学知识。作者发布记录同时包含 `pred`、`alt`、`image`、`image_rephrase`、`rephrase`、locality 字段；主评价文件还有 `port_new`。
- 当前公开 release 读取到 train 4,490 条、main 2,497 条、attack 721 条。main 全部 2,497 条的原图与替换图**路径引用不同**；这没有验证像素不同、患者独立或全部临床匹配正确。
- 在 train 的 4,490 个原图路径引用中，3,129 不出现在 main/attack 的任一 image/image_rephrase/m_loc 角色。仅路径不重叠不是完整数据资格；训练记录还带评价字段，不能把整个 JSON 的所有字段都送入监督。
- 作者当前 README 将可靠性数据源指向 GMAI-MMBench，论文构造正文写 OmniMedVQA，需保留这一来源差异并核对实际 release，不能默认为完全同一发布。
- 当前作者仓库根目录只有 README 和 data，没有发布的完整医学模型执行器。当前 pro5000 的既定 MedMKEB 数据目录不存在；论文或 metadata 可读取，不等于该机器上的全部图像已经可用。旧项目关于 131 张可解析训练图全部与评价角色重叠的结论，只针对当时已恢复的图像资产，不代表作者全部训练集都重叠。

适合外部 benchmark 验证：纯 W 目标插入、连续目标保持、文本/图像目标迁移和保护。反事实目标遵循与原始医学来源正确性必须分别列报；不能把 `alt` 当作新的临床真标签，也不能只用 `pred` 字段宣称原始临床标注已核实。

来源：[论文](https://arxiv.org/html/2508.05083v1)、[AAAI 2026 发布页](https://ojs.aaai.org/index.php/AAAI/article/view/40705)、[作者仓库](https://github.com/pkusixspace/MedMKEB)。匿名发布字段/计数见 DATASET_RELEASE_AUDIT.json；原始第三方 JSON 不加入本项目公开提交。

## 本轮执行选择

优先 M3Bench 的现有合法来源，避免直接把医学修复目标换成 MedMKEB 反事实目标。共有两种具体、不同的问题，完整协议必须明确其中一种：

1. **最小严格机制对照**：沿用已准入八编辑和训练锚点，统一完整逐步范数，比较 C/U/H。第三轮 C 的每步日志和输出若全部绑定相同，可作为明确登记的复用参照；不重复已完成的 C 训练/评分，不声称独立新数据验证。
2. **新的 M3Bench 来源队列**：可由角色合法的源 QA 构成新编辑请求，T1G/T2G 保持未训练评价；H 回放历史已写入源请求。额外 GFIT 只有在来源作用域已验证时才加入，否则采用明确的源监督设计，而不是偷用评价题。这会改变相对前三轮的监督与数据，必须在新协议中写清，不能把跨轮差异仅归因几何或历史项。

24 个新单元是可选实验规模。若采用第二项，不得把第一项的现成来源/锚点合同假装已经支持新的监督队列。C/U/H 都继续只写原 W，零新推理参数；GPU 仍只允许 5，前三轮结果和已失败评分保留。

本次搜索完成了来源/定义核对并修正不必要的硬门槛，没有自动启动 MedMKEB 实验、扩充 GPU、改动旧结果或临床标签。正式冻结与启动还须完成所选队列的角色映射和对应训练/续跑/评分适配。
