# 累计编辑与生成实现机械核对

用户于2026-10-26明确要求先排查累计编辑和生成实现，有错误则修复继续，并保留已有结果和失败。此次只核对实现，不优化比较方法或更换冻结配方。原完成授权、最多三张物理GPU、50GB新增存储保护保持。

## 来源与检查

逐项对照 MEMIT 固定提交80426fd9316cf9a50c5ba15e0912f2c2c5bfe84b及EasyEdit Mistral固定配置b56ce8a300cf09410e93eb30643df86dd0a0ff6d：目标激活位置、因果前缀、五上下文损失、KL方向、梯度累计、层4–8的原生残差分配、rank-one协方差求解、权重累计及恢复、生成缓存和EOS。

隔离复算仅使用已授权训练native+FIT4+image-only KL，同样原顺序和seed，从Base机械重建前6次；不读取评测正确率，不选择更好超参。最多6次诊断编辑、2500 forward、1000 backward、150 latent更新；不构成新的比较结果。必要前16个token作为诊断输出，只核对已落盘序列的一致性，不调用Judge、不覆盖既有答案。

对每次编辑，记录优化后的目标及每层更新前的实际key/当前激活，独立按原矩阵公式计算预期权重，验证物理写入没有重复、转置或遗漏。核对prompt截断前后的lookup激活及EOS标签；如浮点差异出现，报告差异，不为通过而改变阈值或参数。严格逐元素写入检查优先，前缀激活比较rtol=1e-5/atol=5e-4。

## 运行隔离和保留

在当前三张卡之一做隔离诊断；同卡原辅助生成worker暂时SIGSTOP保留其显存、KV、计数与在途状态，诊断由独立CPU父进程负责finally恢复，避免丢失原消费者。不停止其他项目。显存检查及诊断进程内分配上限预留4GiB，30分钟单次诊断超时只终止诊断并恢复辅助worker。三张物理卡上不新增第四张。存储仍由当前整体独立守护覆盖，诊断仅写小型计数/元数据，不追加checkpoint归档。

如发现实现错误，保留原运行与输出为旧实现证据；另记修复版本、影响范围、回滚/重建所需状态并验证后继续。若复算复现原轨迹且未发现机械错误，如实报告未排除的限制，不把生成退化自动当成代码错误，也不通过截短输出或重复惩罚改变本轮。

## 初始化显存失败与诊断后端修复

首次隔离尝试在协方差求逆的GPU工作区分配失败，已记录18.498802秒进程成本，0模型forward、0backward、0编辑、0生成；原辅助worker已自动恢复。失败目录保留。第二次诊断只把初始化的同一协方差双精度LU求逆置于CPU，矩阵、系数和公式不变；实际模型/梯度/生成仍在原GPU上，显存4GiB余量不放宽。该更改只用于隔离诊断，不修改正式实现。原历史范数允许报告CPU/GPU数值后端差异，不把不一致直接当作源轨迹错误。

## 因具体数值差异追加同后端机械核对

CPU求逆版本在前三次的前缀、写入和范数基本复现，但第4次delta范数出现约1.38%差异，生成前缀不再相同。该差异保留，不称严格复现通过。为排除诊断自身改变后端的混淆，追加且仅追加一次相同前6次的机械复算：加载大模型前在同型GPU上按正式代码计算五个float64逆矩阵，暂存在CPU内存；随后加载模型并复用这些GPU计算的逆，避免求逆工作区与大模型同时占用显存。矩阵、系数、数据、seed、公式和浮点精度均不改，不落盘大型逆矩阵，不挑选输出或优化超参。

两组诊断各6次、总计最多12次机械重放（首次显存失败为0编辑），合计最多5000 forward/2000 backward/300更新，全部成本相加不重置。正式292次编辑的轨迹不混入诊断，也不复用这些诊断权重替代原结果。如仍不一致，如实报告数值敏感性与未排除项，不继续无限追加机械重放。

同后端诊断另保留第1与第6次编辑的五层key和adjusted-key（约2.3MB私有小型张量，不含checkpoint），在模型退出、原辅助worker恢复后做恰好10次CPU float64官方直接线性求解 `(15000 C + k k^T) a = k` 对照。预先以adjusted-key范数相对误差1e-8及方程相对残差1e-5为机械判据，全部10项均报告；不依表现挑key，不产生额外模型编辑或Judge调用。若有差异则报告并核对，不修改阈值凑通过。
