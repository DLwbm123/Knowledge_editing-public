# 显存准入故障与有限接管

2026-10-11 15:25 UTC 的监测确认：C8 精确复现与 Base 算子 Fisher 已通过；两个训练分区在模型加载前因空闲显存小于 45 GiB 退出。两份失败记录的所有计数均为零，分区对应的新臂无候选、活动恢复点或进度记录。另一分区的健康训练持续运行，本次修复不重启该 worker，也不读取恢复点来续训。

用户随后明确授权 GPU7。本次硬件许可为物理 2/3/4/7，同时最多三个训练 worker。分区仍为原 3/3/2 个 owner；六臂、数据、种子、160 步、7168 参数、显存门槛及所有预算保持不变。

`module_recovery.py` 仅接管记录中的健康 PID/start_ticks，补启动两个经验证为零模型工作的分区。空闲显存检查在创建 GPU worker/租约之前进行，优先使用 GPU7；不足则等待，不改变门槛、不占用其他用户进程、不重复训练。完整启动记录、失败与零计数均归档到私有工程证据目录；两次失败租约仍计入原账本。原控制器等待自己的健康子进程并退出后，接管程序复用公共 `finish()` 完成原已登记的冻结、评估、评分与生命周期流程。

后续评估和自然路由也使用同一准入调度，不按结果选择 GPU 或 owner。正常路径 11 个租约加两次零工作失败，共 13 个租约；报告必须验证全部结束。评分仍在全部候选冻结和生成完成后才开始；停止过的四个 worker 保留原状态与同一评分 epoch，仅恢复未尝试队列。

自检验证拒绝非准入失败、非零训练/前向计数、空计数；调度检查覆盖三个分区在唯一可用 GPU 上依次启动，不重复同卡并发、不漏分区。语法和 diff 检查通过。尚未获得完整训练或评分结果，不声称提升。此入口不支持任意训练中断恢复；健康 worker 若中途失败，必须停止并另行核验完整恢复状态。
