# 固定 16 MiB 输入保护器：实现与 CPU 检查

状态：CPU_ENGINEERING_PASS；一般 FP16/BF16 子空间写回阻塞；不具备真实实验启动资格。

## 实现范围

新增 experiments/fixed_input_guard_v1/guard.py 与 cpu_check.py。旧 HE/HM 执行器、历史结果和协议不变。保护器是独立 CPU 张量组件，没有模型加载器、服务器连接、训练入口、Judge、部署或自动运行链。

接口：select_inputs(views) 在调用方固定的1–5个视图顺序中均分32个位置，视图内等距取样（短视图不补采样）；InputGuard(base_inputs) 以至多32个校准激活建立固定Base基底；write(weight, optimizer_delta) 投影最终优化器更新并原地写回、认证、必要时回滚；admit(inputs, successful=...) 仅在调用方显式判定整条编辑成功后更新历史；state/restore提供固定模式的张量状态恢复。输入仅限CPU，所有矩阵更新在no_grad下进行。真实模型激活hook、原Base teacher、H/HE目标与优化器接受/拒绝事务尚未接线，不宣称生产执行器完成。

持久状态只有5个固定形状张量：Base 14336×32、history 14336×64、sketch 128×14336（均FP32），4个int64计数和1个FP64丢弃误差标量。合计12,845,096字节（约12.25004 MiB），序列化12,847,116字节，均小于16 MiB。单个保护器只维护一份当前状态，历史数目不参与任何张量形状。溢出计数拒绝继续。禁止外部调用方逐编辑保存此状态。

16 MiB是单份持久保护统计上限，不含模型、W、当前梯度、投影中间量、恢复/原子保存的临时副本。当前CPU认证使用FP64中间量，完整矩阵检查需要GiB级固定工作内存；本轮未测峰值RSS，不能声称总内存仅16 MiB。生产端如优化为分块，须再认证等价性。

## 数学与低精度边界

D为最终优化器建议更新，Q为当前Base和history合并后重新正交化的基底。投影为D−(DQ)Qᵀ，不构造完整输入协方差或投影矩阵。真实写入后，重新读取native W，以FP64计算 Δ_actual = W_after−W_before，再检查：

||Δ_actual Q||_F ≤ 1e−7 + 1e−6 ||Δ_actual||_F。

写回容差在检查前固定，未按结果放宽。为防止已受Base保护的输入因浮点误差生成伪历史方向，基底构造采用FP64 SVD后存FP32，Base残差归一化范数及奇异值的数值零阈值为1e−6；低于此阈值的方向视为数值零，不宣称精确保留该部分能量。非有限候选不写入；零native更新判拒绝；残差超限回滚；异常回滚并重新抛出。不重试、不缩步、不偷偷转存FP32。拒绝的更新不改变W，调用方也不得推进优化器、历史或成功计数。该模块尚不管理外部优化器状态。

保证只涉及实际矩阵更新对当前输入基底的作用，不保证最终输出、语义、旧答案或证据margin。Base基底固定，history通过Frequent Directions式固定行摘要压缩，丢弃能量有标量诊断；有限精度FD检查是合成数值oracle，不是严格区间证明。旧方向可以被淘汰；历史编辑成功判断由调用方提供，模块不能自行证明语义成功。

## 实际 CPU 检查

环境PyTorch 2.6.0，CPU两线程，seed 1616，无模型/数据/Tokenizer/GPU/Judge调用。最终回执CPU_CHECK.json，耗时约7.37秒。三次完整检查均通过；第二次增加全形状一般子空间、异常输入和固定位置选择检查；随后单独审查发现重复Base输入会因数值残差产生32个伪历史方向，修复并在第三次完整检查中加入回归断言。

- 128维连续2,000次摘要更新：第1/146/1000/2000次状态均114,728字节；checkpoint均116,748字节。每步检查状态大小及冻结Base，保留/压缩行数固定。
- 独立累计协方差oracle：最大丢弃方向能量17.04200，摘要丢弃上界17.24759；最小差异约−2.63e−12（浮点误差）。
- 变化历史基底下146次非零FP32实际写回全部通过，独立复算残差最大为阈值的0.546倍。
- 真实维度4096×14336：历史摘要经过压缩，持久状态约12.25 MiB；一般FP32实际写回相对残差1.70e−8，通过。
- 同维度一般FP16实际写回相对残差1.40e−4，超过预定容差，被拒绝并验证W恢复。128维一般FP16/BF16也分别拒绝（约3.37e−3/2.97e−2）。
- 坐标对齐的非零FP16/BF16写回通过，完整形状FP16残差为0；这只是可通过的构造样例，不能代替一般子空间结果。
- 固定视图取样、零/极大有限输入、恢复前后后续写回等价、失败编辑不入库、NaN/零更新/溢出拒绝、损坏基底恢复拒绝通过。

结论：固定存储与“超限不提交”行为通过；“一般低精度写回可接受”未通过。CPU整体PASS表示拒绝逻辑按预期工作，不能解读为FP16方法有效。不得据此自动启动模型实验。

## 最小后续验证方案（建议，尚未授权/未执行）

1. 先处理低精度写回阻塞。在原生FP16约束下设计可认证写入，或由用户明确决定是否允许被编辑层采用FP32。当前实现不自动选择其中任一路，不放宽1e−7/1e−6门槛。候选修复先用全形状、一般子空间CPU检查，要求非零可接受更新；全拒绝不算通过。不能因坐标样例通过而跳过。
2. 通过后再接真实执行器，仅一次真实模型准入：当前层激活提取、固定视图选点、实际optimizer delta、拒绝时optimizer/master/RNG事务、native保存重载、当前成功门后admit。保持原Base teacher；单独证明CPU组件已接入真实更新路径。CPU合成检查不能代替此准入。
3. 最小科学验证建议用固定原顺序前8条连续编辑，两个独立Base起点串行臂：H-only无历史保护、H-only固定16 MiB保护。每条20槽，共320槽，Base32/history64、视图取样规则、原成功/保护门与容差全部预先固定。先测试保护器，不同时比较H与H+E。只看0/4/8三个前缀；评估新编辑成功、旧编辑保留、预先固定且不用于校准的保护题、拒绝/零写比例、状态大小和实际运行峰值。
4. 若新增编辑几乎全被拒绝、历史保护无改善、成功率损失超出事先冻结门或任何存储/写回门失败，停止并报告；不自动加秩、改容差、加步数或扩至146。正式运行前仍需另行冻结精确样本/评分量、GPU与墙钟预算，当前仅给出最小对照结构，不是一份可执行启动协议。

复现CPU检查：在已安装PyTorch的CPU Python中，把experiments/fixed_input_guard_v1加入sys.path后调用cpu_check.run()。不需要下载或读取模型和数据。
