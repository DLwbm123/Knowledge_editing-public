# 用户批准：按依赖顺序执行与 checkpoint 生命周期

生效日期：2026-09-13。适用 MedTRACE 后续实验，包括租用 GPU 服务器与
my-gpu 共享存储。取代 STORAGE_POLICY.md 中“默认把历史 checkpoint
迁往归档盘长期保留”的建议；不修改已冻结科学协议和历史结果。

## 执行顺序

1. 在查看方法结果之前锁定所有已授权方法、队列、single/sequential/prefix
   和必要机械验证清单。列出每类 checkpoint 的最后一个必需消费者及空间预算。
2. 按方法衔接其 single 训练/生成、可复用专家的 sequential 插入与全库生成、
   已约定的 save/load 检查，再结束该方法的 checkpoint 生命周期；避免先堆积
   所有方法的 single 权重，等待全部 Judge 后才进行连续编辑。
3. 只有真正独立的编辑可分批；有状态 sequential 不拆成互相独立的 single。
   仍需保留完整专家库的算法，不可通过提前删除旧专家来改变系统语义。
4. 生成后的完整 Judge 材料可先排队。云端评分可与后续 GPU 工作重叠；评分
   尚未完成本身不要求保留权重，只要所有需要权重的已授权工作已经完成，且
   冻结的参考、回答、tokens 和绑定材料已完整落盘。不得根据评分好坏决定
   是否执行预先登记的方法，也不得自动追加实验。
5. 若某个必需消费者尚未实现或不能启动，将依赖明确标为待完成。优先补齐
   已授权的消费者，不能默默删权重导致重训，也不能以“以后也许有用”无限保留。

## 默认删除规则

用户已授权后续实验将无后续依赖的生成 checkpoint 删除，无需每份再次询问。
执行前必须针对当前项目解析明确的文件清单，并同时确认：

- 相应训练/生成/必要状态验证已完成，文件不是当前或最新必要的 resume 状态；
- single/sequential/prefix 等已登记的消费者已全部完成，不再需要这些权重；
- 结果、Judge 输入、原始输出/token、配置、来源及执行绑定、计数/失败记录和
 复算代码均完整可用，评分可独立复算；不把“模型生成了答案”当成验证完成；
- 文件所属主机、绝对路径、挂载、符号链接目标和使用进程已确认，作用域只限
 该实验的生成 checkpoint/optimizer 临时状态，不包含原始数据、共享预训练
 模型、环境、其他项目或未经核实的历史文件。

删除以具体文件清单执行，不递归清空项目、home、共享盘或整批实验目录。
生成小型删除回执，记录原因、完成依赖、文件数量、字节数、是否有保留副本及
重建条件。原始路径回执保持私有；公开仅脱敏汇总。默认不计算全量哈希。
没有副本的权重删除不可直接恢复，应明确记录需要重训才能重建。

这不是立即删除当前 BalancEdit 146 份 checkpoint 的命令：它们尚有 Stage17
连续编辑复用依赖，先完成相应消费者再删除。本次只更新约定，没有删除文件。

## 少量保留例外与小文件

- 外部基线没有默认永久权重配额；“报告已出”不是唯一条件，最后一个必要
 权重消费者完成后删除。不要将所有基线权重转移到 my-gpu 代替删除。
- my-gpu 可以保留用户自有 MedTRACE 方法的少量必要 checkpoint，例如确需
 保留的复现/部署状态。每份写明具体用途、数量、字节预算和复核/删除条件；
 优先只保留达到目的所需的一套，不保留所有 seed、编辑、step 或重复目录。
 未说明必要性的权重不属于例外；该例外不是扩大训练或按分数筛选确认集的授权。
- 长期保留代码、配置、协议、支持分母、报告、指标、评分及必要输出和绑定。
 数据/输出中包含私有材料时保留在合法私有位置；GitHub 只发布许可范围内
 的代码和脱敏聚合。大量 tokens/逐样本记录可以无损压缩，不删掉复算所需证据。
- 预训练 Base、视觉模型、仍在用的 Judge 权重及环境不是每方法产出的 ckpt；
 复用单份，不在此规则下自动删除。另行清理需要确认其依赖和范围。

## 容量与中断

开始方法前估算完整生命周期峰值，包括活跃专家库、原子保存临时文件和输出。
新写入前保留至少现有 8GiB 余量；容量不够在阶段边界停止并保留恢复点，
不牺牲科学合同、不抢删活跃状态、不回退系统盘。其他写入者可能消耗空间，
所以不承诺有限磁盘永不耗尽，也不靠默认无限归档实现持续运行。

本文件是调度和删除授权约定，不是已经部署的自动垃圾回收服务。每个实际
worker 的清理入口须遵循上述依赖检查，在下一次锁定调度时落实；不热改当前进程。
