# T5 原论文、发布仓库与本地实现对照及修正

已核对论文 arXiv:2607.05310v1，以及官方仓库固定提交 `03c6fda3813301dab3be5831fdc94b493c10afc9`（提交日期 2026-06-28）。检查的是实际文件和仓库树，不把 README 的叙述当作已运行代码。

## 能确认的差异

| 项目 | 原论文／官方公开发布 | 原本地实现 | 本次修正 |
|---|---|---|---|
| T5 主指标 | 发布规范明确 `delta_ACC = ACC_after(T2) - ACC_before(T2)`；论文是“1 减编辑后在随访中引入事实错误的比例”的文字描述，未给出可唯一恢复分母的 T5 公式 | 把 `1 - count(pre-correct AND post-wrong)/全部编辑` 作为主指标，ΔACC 只列为次指标 | 以可核验的发布规范为准，主报 ΔACC（百分点），并列编辑前后准确率；旧主指标只保留在历史报告 |
| 编辑入组 | 既往 T1 回答错误 | 还要求 T2 的 Base 评分已知 | 去掉 T2 已知门，新增 11 个原本 T1 已判错的病例，单次共 159 例 |
| 连续编辑名单 | 公开规范未规定全局影像角色安全排除；也没有公开 T5 连续编辑实现 | 全局排除“某病例既往影像也是其他病例随访影像”的任务，连续编辑仅 144 例 | 新发布规范对齐版本按同一 159 例原顺序运行。原来额外排除的 4 例重新进入最终库；明确披露跨病例影像曝光，仍仅为 DEV，不能宣称独立未见病例表现 |
| 缺评分 | 文档要求正确性布尔值，未规定基础设施评分失败的恢复办法 | 未知评分导致样本被排除 | T1 未知的 154 例资格仍未解决，不冒充已判错；已知 T1 错误的 159 例中，11 个 T2 未知留在固定分母，以不确定范围报告，不补零、不默默重试 |
| 正确性判定 | 公开 YAML 允许 fuzzy 或 LLM | 当前 CORE LLM 合同 | 保持 CORE 合同和已接受判断，不以换 Judge 改变样本或结果；不能声称复原作者未公开的实际 Judge |

原先 144 例只有 1 个随访预正确病例，因此旧主指标数学上最低就是 143/144=99.31%，不编辑 Base 的旧主指标则为 100%。这不是发布版 ΔACC 的计算方式。原始 99.31% 不删除，但停止将它作为发布规范下的 T5 主分数。

## 论文与仓库自身未对齐的部分

- 论文给出 T5 数值表，并描述 324 个编辑实例、440 张影像、43 种疾病。
- 固定版本的 T5 README 仍说明参考实验尚未运行 T5；根 README 的论文与数据集链接还是占位符。该仓库提交早于论文日期，不能将它当作完整同步的论文实验包。
- 仓库只有四个 Python 文件：通用 T0–T4 构建器、两个公共辅助文件以及 T1G 图像扰动构建器。`TASK_BUILDERS` 不含 T5；没有 T5 构建器、计分执行器、作者病例清单或 PadChest-GR 处理后元数据。因此没有可直接运行并恢复论文 T5 表格的官方程序。
- 预测格式要求按同一患者、同一问题、时间先后配对。本地使用 PadChest-GR 的显式 `PreviousStudyID/PreviousImageID` 源链接；已有的双日期／患者交叉验证保留，无法获得的既往日期保持空值。不能伪造日期来宣称完整通过作者的配对实现。
- 本地源表实际有 324 个进展行，合并两个完全冗余的影像对／病征／二值标签后为 322 个 canonical 任务，使用 435 张唯一影像和 67 个原始标签。保留源行映射和去重说明；没有作者病例清单，无法确认论文的 440 张／43 类来自哪个版本或映射，不能强改标签与数量来“对齐”。

因此，本次交付应称为“**公开发布规范对齐的 T5／同 CORE 判定**”，不能称为“论文 T5 表格的精确复现”。作者论文表中的 45%／58% 等数值仍不能直接用于本地排名。

## 本次实际修正与运行

1. `experiments/med_t5_release_alignment_v2/metrics.py` 实现固定分母的前后准确率与 ΔACC，并对未知判断计算保守范围；新增测试覆盖不编辑 Δ=0、收益与损伤抵消、未知随访保留和缺预测不缩分母。
2. 新单次与实际最终库均为 159 个已确认 T1 错误的 canonical 编辑。旧的单次 148／连续 144 结果仍保存；`LEGACY_COHORT_DELTA_ACC.json` 仅是旧名单的离线指标重表达，不冒充 159 例修正版结果。
3. MDU 保留并复用已有 148 个专家，只对新增 11 例运行原 C160+MED160+MDU160 配方。对旧 single 回答必须校验原输入、所选专家与状态标识后才复用；新最终库的回答重新生成。
4. BalancEdit、GRACE、LoRA 按之前冻结的标准配置重建修正队列。其已消费对比状态已按生命周期退休，不能拿旧 144 库回答冒充 159 库结果。MEND 缺匹配且来源可验证的已训练编辑器，仍不填分数。
5. 当前只够两个 60GB 显存余量准入槽，采用 MDU→GRACE 与 LoRA→BalancEdit 两条顺序 GPU 队列；不终止或改动旧协议剩余 GRACE 作业。新队列自己的原始 23 小时时钟包含所有排队、训练、生成和评分，不重置。

修正后已知资格集合依然是“11”155 例、“10”4 例、“01”0 例；恒定 Yes 的准确率为 155/159=97.48%。这仍是明显偏斜的局部队列。修正指标和排除门不会自动产生可靠的时序能力证据，必须与恒定答案控制和各进展分层一起解释；不按方法结果重平衡、删样本或扩张源数据。
