# T4G 组合泛化复核

本次仅复算已冻结回答、评分和训练回执，没有重新训练、调用模型或 Judge，也没有改变既有结果或样本名单。复核脚本为 `experiments/med_t4_core_v1/audit.py`，聚合证据见 `T4G_AUDIT.json`。原始逐例材料与状态回执保留在私有目录。

## 结论

未发现造成低分的汇总、样本接反、输入绑定或专家状态绑定错误。22 项检查通过：单次编辑 13.005952%，最终库 14.434524%，均按原先冻结的逐编辑宏平均精确复现。不能把这次检查解释成已经排除所有运行或标注问题；它覆盖现存输入、输出、评分和回执的一致性，没有独立重新推理或临床复核。

低分不能主要归因于路由未触发：单次编辑 95 次探测中 94 次激活所属专家，只有 1 次 OFF。已核对该 OFF 回答的 token 与对应 Base 存档一致。T4G 没有生成达到长度上限的回答，方法评分没有 UNKNOWN。

## 实际任务负担

32 个编辑对应 95 次探测，但只有 12 个唯一探测问题/影像，涉及 25 个唯一编辑影像，不能把 95 次探测当作 95 个独立病例。95 次探测中 87 次参考答案不同于对应编辑的参考答案；这些探测并非原答案的直接复述。

按固定的字符串规则描述问题形式（仅作诊断，不能据此重选样本）：

| 编辑问题 → 探测问题 | 探测次数 | 单次答对 | 最终库答对 |
|---|---:|---:|---:|
| 疾病识别 → 位置 | 56 | 0 | 10 |
| 疾病识别 → 颜色 | 7 | 0 | 0 |
| 位置 → 位置 | 17 | 8 | 3 |
| 存在性 → 存在性 | 4 | 1 | 1 |
| 其他形式组合 | 11 | 0 | 1 |

因此，63/95 次探测同时要求从疾病识别迁移到位置或颜色回答。当前结果同时包含组合迁移与属性问答的难度，不能全部归因为多病征共现。问题形式分类不替代临床标签，也不是新的主结果。

从原始 T4G 组成表中只解码这批已入组影像配对对应的 75 行元数据。全部包含相同目标病征，且目标影像均标注至少两个病征；95 次探测的编辑影像和探测影像均不同。没有发现单/多病征配对接反或目标病征不包含于多病征标签的情况。这是源标注一致性检查，并非对图像的独立临床验证。

## 最终库的路由现象

冻结协议使用共同包含 32 个 T4G 编辑与 35 个 T4L 编辑的真实最终库。95 次 T4G 探测全部 ON，但只有 1 次选择对应编辑的专家，94 次选择其他专家；其中 70 次选中来自 T4L 队列的专家。55 次所选专家的编辑影像与探测影像相同，但没有一次所选专家的原始编辑问题与探测问题完全相同。

这符合当前 R0 按距离选择专家的实现，并非此次代码把专家 ID 接错；但它暴露了共享库下的选择竞争。其他专家可能学习相同病征，也可能学习其他病征，不能将“其他专家”一概视为错误路由。仅凭存档不能证明强制所属专家会提升最终库结果，且所属专家单次运行仍只有 13.01%。

## 指标与实现核查

- 独立使用有理数复算逐编辑宏平均，全部 T0/FIT/T4G/T4L 的 single/bank 主结果复现。T4G 事件微平均分别为 9/95=9.47% 和 15/95=15.79%，与宏平均不同是正常的分组权重差异，不能替换原指标。
- Base 的编辑输入均已判错，T4G 探测均在编辑前判错；合格编辑集合与冻结名单相同。
- 每个训练条目只有原始影像/参考及原始问题和四个 FIT 视图，全部 token 绑定通过。67 个编辑合计 32,160 步更新，两个训练分片正常退出。
- 每个生成回答均能对应计划中的影像、问题、参考；原始问题和任务探测的 prompt token/attention mask 与 Base 存档相符。未发现相同影像与问题绑定多个参考的冲突。
- 回答的所用状态标识与最终库现存状态标识一致；此处复用已保存的标识，没有新增权重哈希。单次编辑激活时均选择自己的专家。
- Judge 实际收到的问题、参考、完整回答与生成记录一致；没有把 FULL 分数当 CORE，也没有修改已接受判断。

## 后续解释边界

保留原来的负结果，不删除属性迁移困难的样本来提高主分数，不在该已暴露集合上搜索半径、层位或提示。若后续改进主线，应另行冻结开发实验，区分源数据任务构成、单专家跨属性迁移与多专家选择竞争，并在独立、同口径数据上验证。当前结果不能直接与原论文全量样本的数字作优劣结论。
