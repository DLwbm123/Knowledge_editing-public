# M13固定160步循环与来源/状态准备

trajectory.py仅提供新四类轨迹的固定160步循环，不提供GPU启动器或自动恢复入口。逐编辑来源只读取原版本资格通过的原题、四FIT和两GFIT，固定NATIVE/FIT/GFIT七源顺序；未合格编辑拒绝。当前仅七例合格，146入口仍必须先完成整个数据和运行准入，不能据单例helper可执行绕过139例来源缺口。

循环直接调用原module_run.source_gradients：每步native .25、一条循环FIT .25、一条循环GFIT .5，恰好三次源反传。调用已精确验证的C/M3 Adam+RAW或M1/M13规范两标量RMS路径；M1/M13只在冷起点规范化一次，C/M3不规范化。全四核7168参数、零G1与非零其余核起点、原160节点C步幅、软系数和每步预算检查固定，不加90%收益或方向跳步。M3/M13每步各一次算子正则反传，局部求解零。

每20步交付完整核、优化器或两RMS、完整曲线、原源顺序/seed/算法/预算/scope绑定、累计计数，以及PyTorch CPU/当前GPU、Python和NumPy RNG。快照检查拒绝时钟、源顺序、seed、计数和非法Adam矩；未提供盲恢复或迁移。实际训练中断仍须独立的真实网络损失、RNG、数据版本和完整预算/锁审计，不能仅据本CPU快照检查续跑。

CPU夹具使用只读真实7168 C BASE、合成的可微随机替代损失和小Fisher缓存，运行C/M1/M3/M13各160步。每类480次替代源反传、八个20步快照、160次预算调用检查；M3/M13各160次替代算子反传。源选择顺序精确，保存加载后核相同、三类CPU RNG的下一抽样一致；seed/源序/优化器时钟/计数/非法Adam矩变化和未资格来源被拒绝。夹具预算回调只验证到达每步检查，不冒充实际GPU预算和存储准入。全部PASS见TRAJECTORY_CPU_CHECKS.json。这些替代损失不是VLM训练源或性能证据，实际新增GPU租约/VLM/Judge均0，旧ALIGNED模型与计数未修改。
